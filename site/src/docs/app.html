The desktop app

BeeZip's window opens archives in tabs, where you browse, preview, extract and edit them, and it packs files into new archives. This page goes through the window from top to bottom: opening and browsing, every dialog and its fields, the jobs panel, the command palette, settings and updates, and the keys that do each thing.

Getting around

The welcome screen

With no archive open, BeeZip shows its welcome screen: Open archive…, New archive… and Settings, and a drop target. Drop an archive on it to browse it, or files and folders to pack them into a new archive.

Tabs

Each open archive has a tab along the top of the window. Hover a tab to see the archive's full path. Close a tab with its ×, a middle-click, or Ctrl+W.

At the right of the tab strip are Open, New archive, Commands (the command palette) and About BeeZip, which shows the version, a Check for updates button, the formats BeeZip reads, creates and encrypts, and the third-party notices.

Opening archives

  • Open: Open in the tab strip, Open archive… on the welcome screen, or Ctrl+O. You can pick several archives at once; each opens in its own tab.
  • Drag and drop: drop one archive on the welcome screen or the tab strip and it opens. Several files, or a file that isn't an archive, go into the New archive dialog instead. Dropped on an open archive's entries, files are added to that archive.
  • Double-click in Explorer: once BeeZip is installed, it's offered for zip, 7z, rar, tar and the compressed and split formats. Windows asks which app to use the first time you open each kind of file. The portable copy leaves file types alone. See Download.
  • From Explorer's menu: Open with BeeZip opens each selected archive in a tab, Extract to… opens the Extract dialog, and Compress to… opens New archive with the selection. See Explorer's menu.

Launching BeeZip again, such as by double-clicking another archive, opens that archive in the window that's already running, rather than in a second window. An archive that's already open switches to its tab.

A split archive opens from any of its parts, and BeeZip recognises a format by its content, not its extension. Opening a file that isn't an archive says so; drop it on the window to pack it into a new one. Some formats are read through an installed 7-Zip; without it, opening one says so, with Install 7-Zip on Windows, and the tab lists the archive as soon as 7-Zip is installed. See Formats.

Browsing an archive

An archive's tab has a toolbar along the top, the folder tree on the left, the entries in the middle, the preview on the right, and a status line at the bottom.

The toolbar starts with the path to the folder shown. Click the archive's name to go to the top, or any folder in the path to go there. Up one folder (the arrow, or Backspace) goes up a level.

The folder tree

The tree lists the archive's folders. Click a folder to show its entries, and click the arrow beside it to open or close it without going there. Each level is read the first time you open it.

The entries

The table lists the folder shown, one row per entry: Name, Size, Packed, Modified, Method, CRC and a lock for encrypted entries. Beside the packed size, a thin bar shows how much of the entry's size it takes; hover it for the percentage. A symbolic link shows the path it points to.

The entries start in the archive's own order. Click a column's header to sort by it, and again to reverse; folders stay first. BeeZip sorts the whole folder, not just the rows on screen, and a folder of a million entries is fine.

Double-click a folder, or press Enter, to go into it. Double-clicking a file opens it; see Opening an entry.

Selecting entries

  • Mouse: click a row to select it. Ctrl+click adds or removes a row, Shift+click selects every row from the last one clicked, and Ctrl+Shift+click adds that range to the selection.
  • Keyboard: ↑ and ↓ move a row, Page Up and Page Down move 20, and Home and End go to the first and last row. Hold Shift with any of them to extend the selection.
  • Everything: Ctrl+A selects every entry in the folder shown, however many there are. Esc clears the selection.

Going to another folder, or sorting again, clears the selection.

The preview

Select one file and the preview pane shows it, with its size, method and date at the top. Selecting a folder clears the pane; selecting several entries leaves it as it was.

  • Text shows the first 64 KiB, with Load more for the next 64 KiB. Bytes that aren't UTF-8 show as �, and the pane says so.
  • Images (PNG, JPEG, GIF, WebP, BMP, ICO and SVG) show up to 16 MiB. A larger image says to extract it instead.
  • Anything else shows as hex: the first 64 KiB, eight bytes a row, with the printable characters beside them.

BeeZip decides by the file's extension first and, for an extension it doesn't know, by its first bytes. In a solid archive, where files are compressed together, previewing a file means decoding everything stored before it in its block, so the pane asks first: click Preview files once and the tab previews from then on.

When the window is narrower than about 1,000 pixels, the preview pane is left out.

Resizing the panes

Drag the edge between the folder tree and the entries, or between the entries and the preview, to make the tree or the preview wider. The entries always keep some room: the preview gives way first, then the tree. Double-click an edge to put that pane back to its default width. An edge also takes the arrow keys, Home and End once it has the keyboard focus.

BeeZip keeps the sizes for every tab, and for the next time you start it. The jobs panel has an edge of its own.

The status line

The line under the entries counts the items in the folder and the ones selected, says why the archive can't be edited when it can't, and gives the archive's format, its unpacked and packed sizes, and whether it's encrypted or solid.

Extracting

The toolbar's first button says what it extracts: Extract all with nothing selected, or Extract 1 item, Extract 12 items and so on. It opens the Extract dialog for the selection, and so do Ctrl+E and Extract a.zip… in the command palette.

Entries that aren't extracted as stored

Extraction never writes outside the destination. Entries whose paths lead out of it, and links that do, are skipped. Names Windows can't store, such as CON or names with : in them, are renamed, and the result counts them. When anything was skipped for safety, the rest is still extracted, then the job ends with an Unsafe error and a Show report button, which lists the entries skipped, and why, and the ones renamed. Extracted files keep the archive's downloaded mark, as Explorer's do, so Windows still warns before opening a program from a downloaded archive. Safety has the details, and Settings changes the defaults.

Creating archives

New archive (Ctrl+N) opens the New archive dialog. So do files dropped on the welcome screen or the tab strip, and Compress to… in Explorer's menu, with those files already in it.

Editing an archive

You can add to, delete from and rename entries in zip, 7z, tar, cpio and ar archives, tar and cpio compressed or not. Each edit runs as a job, and when it ends the tab lists the same folder again, with the same entries selected.

Adding files

Add files… and Add folder… in the toolbar pick what to add, then open the add dialog. Dropping files on the entries opens it too, with the dropped files: the dialog is the confirmation, so a stray drop changes nothing. While you drag over the window, it says what a drop there will do.

FieldWhat it does
Files and foldersWhat goes in, as in New archive.
Into the folderThe folder inside the archive, which starts as the one shown. Empty is the top. A folder that isn't there is made.
Already thereWhen the archive already has an entry at a file's path: As in the settings (the default, naming what Settings says), Ask each time, Replace the archive's entry, Replace it if the file is newer, Keep both, adding the new one as “name (1)”, or Skip the file.
Method and LevelFor the new files. In a compressed tar the whole archive is compressed again, at this level.

Add starts the job.

Deleting entries

Delete in the toolbar, or Del, deletes the selected entries. A folder takes everything in it. Windows' own dialog asks first (“Delete 3 items from a.zip?”), since it can't be undone.

Renaming an entry

Rename in the toolbar, or F2, turns the selected entry's name into a field, with the name before its extension selected. Enter saves and Esc cancels, as does clicking elsewhere. A name can't be empty or contain / or \. When the new name is taken, or the rename fails, the reason shows beside the field and you can try another. Renaming a folder renames everything in it.

What can't be edited

RAR archives, split and self-extracting archives, read-only files, and the formats BeeZip only reads (or writes but doesn't edit, such as CAB and the disk images) can't be edited. For those, the add, rename and delete buttons are disabled: hover one, or look at the status line, for the reason. Files dropped on such an archive's entries open New archive instead, saying why. Convert turns a split or self-extracting archive into one you can edit.

How an edit is written

BeeZip never writes into the archive. It writes a new one beside it and swaps it in, so an edit that fails, or that you cancel, leaves the archive as it was. Entries that stay are copied without being decoded: zip entries byte for byte, whole 7z blocks, and tar, cpio and ar members. A solid 7z block that loses an entry is encoded again, and so is a compressed tar's or cpio's stream. The archive keeps its downloaded mark, hidden attribute and creation time.

Opening an entry

Double-click a file, or press Enter on it, and BeeZip extracts it to its temp folder and opens it:

  • an archive BeeZip reads opens in a new tab;
  • a program, script, installer or shortcut asks first: “Run setup.exe from a.zip?”, with Cancel focused, so Enter doesn't run it. Windows checks a program run this way as it does a download;
  • anything else opens in the app Windows uses for its type.

An entry over 16 MiB shows its extraction in the jobs panel. Opened files stay in the temp folder while an app may still be using them; BeeZip clears out those older than a day.

Updating the archive after a change

Change a file you opened from an archive, save it, and come back to BeeZip. It asks: “readme.txt was changed. Update it in a.zip?”

  • Update puts the changed file back in place of the entry. An encrypted entry is added with the password you typed for the tab.
  • Not now leaves the archive alone. If you change the file again, BeeZip asks again.

Closing the tab forgets its opened files. A file whose name BeeZip had to change when extracting it isn't offered for updating.

Dragging entries out

On Windows, drag selected entries from the table onto Explorer or the desktop. BeeZip extracts them when you let go, as 7-Zip does, so Explorer waits until they're out. The extraction shows in the jobs panel, and asks for a password if it needs one.

  • Move or copy: a plain drag moves the files out of BeeZip's temp folder; hold Ctrl to copy them instead. Either way, nothing leaves the archive.
  • Where they land: entries arrive without the folders above the one shown. Dragging report.pdf while you're in docs/2026 drops report.pdf, not docs\2026\report.pdf.
  • Several entries: pressing on one row of a selection keeps the whole selection, so a drag takes all of it. A click without a drag selects just that row.
  • The 2 GiB rule: a selection of more than 2 GiB doesn't drag. The Extract dialog opens for it instead, saying why: Explorer would stop responding until it was all extracted.

BeeZip never drops entries on its own window.

Test, Info, Convert and more

Test

Test in the toolbar reads every entry back and checks it against its CRC, without writing anything. When it passes, BeeZip says “a.zip is OK”, with how many entries and bytes it checked. A disk image read through 7-Zip stores no checksums, and the result says what was checked instead.

Info

Archive info (the i in the toolbar) shows the archive's format; the program that reads it, for formats read through 7-Zip; the levels of a disk, such as gpt › ntfs, and a volume's label; how many entries, files, folders and links it holds; its size, packed size and ratio; the methods; whether it's encrypted (none, some entries or every entry, and whether the names are too); whether it's solid, and in how many blocks; and its volumes, comment and notes where it has them. The dialog also has the tab's name encoding.

Convert

Convert… in the toolbar writes the archive again in another format, or with other options. The source stays as it was. The dialog is New archive's, with Source in place of the files: the new archive starts beside the source with the same name and the new extension, as 7z for a zip and as zip otherwise. Leave out skips entries, and Split into volumes splits the result.

  • Encrypted sources stay encrypted: give the new archive a password (the tab's is filled in when you've typed it), or tick Write a.zip's encrypted entries without a password. Formats that can't be encrypted, such as tar, need the tick.
  • Copies where it can: converting to the same format, with no option asking for something else, copies entries without decoding them. a.tar.gz to a.tar.zst copies the tar entries and compresses the stream again.
  • What the new format can't hold, such as a symbolic link in a format without links, is left out, and the result says how many entries were.

Name encoding

Some archives store names as bytes rather than Unicode: zips without the UTF-8 flag, and tars, among others. BeeZip reads those as UTF-8 when they are, and otherwise in Windows' own code page. When an archive's names look wrong, it was probably written in another code page: choose Name encoding for a.zip… in the command palette, or Name encoding in the Info dialog, and pick one under Read the names as, such as Japanese, Shift-JIS (932) or DOS, Cyrillic (866). The tab lists again from the top, and every command on it uses that encoding until you close it. As in the settings goes back to the default, which Settings sets.

Benchmark

Benchmark the codecs… in the command palette opens the Benchmark dialog. Each codec compresses and decompresses a sample in memory; nothing is written.

  • Sample: BeeZip's own, 8 MiB of text, JSON, code, binary tables and random bytes; or a file of yours, read as 16 slices across it.
  • Cells: the common codecs and levels (about 10 seconds), every codec at every level (a few minutes), or zstd and xz on 1, 4 and all threads (64 MiB, about a minute).

Run starts it, and each result appears as it finishes. The chart plots size against speed, with Compression speed and Decompression speed to switch between them; hover a point for its numbers. The table under it has every cell: codec, level, threads, size, both speeds, the memory each way, and the time. Cancel stops it, and so does closing the dialog.

The jobs panel

Everything BeeZip extracts, creates, tests, edits or converts runs as a job, in the panel at the bottom of the window. Until something runs, the panel is a status line saying No jobs. It opens when a job starts; Hide and Show close and open it, and Clear finished takes away the jobs that have ended. Quick work, such as listing a folder or reading a preview, doesn't show here.

Each job

  • While it runs: a progress bar, the bytes and entries done out of the total, the speed, and the file being worked on. Cancel stops it and removes any files it had started writing.
  • When it ends: one line saying what it did (“Extracted 214 files, 18 MiB, to C:\Users\you\Downloads\photos”), or the error. A job that skipped unsafe entries has Show report.
  • Long text: hover a job's title, or the file being worked on, to see all of it.

Logs and Copy

A job that wrote log lines has Log, with their count, which shows them in the list: the first 1,000 lines, then a note saying how many more there are. Copy, on a job with a log or an error, puts its title, its result or error, and its whole log on the clipboard.

Resizing the jobs list

Drag the top edge of the jobs list to make it taller or shorter. Until you do, the list fits its jobs, up to a little over a third of the window. Double-click the edge to go back to that. BeeZip keeps the height for next time.

Closing with jobs running

Closing the window while jobs run asks first: Cancel and quit cancels them, waits for them to remove their partly written files, and closes; Keep working leaves them running.

Passwords and existing files

BeeZip asks these questions as they come up. When several jobs ask at once, the questions come one at a time.

Passwords

An encrypted archive, or an encrypted entry, brings up Password needed, naming the entry. Type the password and click Unlock; the eye button shows what you typed. BeeZip keeps the password in memory for that tab, and passes it to everything you do in the tab afterwards, until you close it. It never saves it.

Files that are already there

When extracting would write over a file and Existing files is Ask each time, BeeZip shows the file's path and asks:

  • Replace or Replace all: write over this file, or every one from now on;
  • Skip or Skip all: keep the file that's there;
  • Keep both: extract the new one under another name, such as name (1).txt;
  • Cancel: stop the job.

Adding to an archive asks the same way when an entry is already there (“notes.txt is already in a.zip”): Replace puts the new file in its place, and Keep both adds it under a new name.

The command palette

Ctrl+K, or Commands in the tab strip, opens the command palette. Type to filter: every word you type must appear in an item. It lists two groups:

  • BeeZip: the app's actions, named after the tab you're on: Open archive…, New archive…, Extract a.zip…, Test a.zip, Add files to a.zip…, Add a folder to a.zip…, Rename in a.zip, Delete selected from a.zip, Convert a.zip…, Info on a.zip, Name encoding for a.zip…, Close a.zip, Benchmark the codecs…, Settings…, Theme: System, Theme: Light, Theme: Dark and About BeeZip. An action that has a key shows it; one that can't run now is greyed, with the reason.
  • Commands: every BeeZip command, as the command line has them. A command with a dialog of its own opens it, and one that takes only an archive runs on the tab you're on. Any other gets a form built from its options, with Run.

Copy as CLI

The Extract, New archive, Convert, add and Benchmark dialogs, and the palette's forms, have Copy as CLI. It shows the beezip command that does the same as the dialog, filled in as it is now, and copies it to the clipboard. A password is left out, and the line says so: the command asks for it when you run it. See The command line.

Settings

Settings opens from the welcome screen, from Settings… in the command palette, or with Ctrl+,. Its sections are Appearance, Extracting, Editing, Creating, Limits, Job windows, Updates, Explorer menu, 7-Zip and MCP server.

  • Saved as you go: each change is written to config.toml as you make it, keeping the file's comments, and the next job uses it. There's nothing to apply.
  • Errors beside the field: a value BeeZip can't take shows its error beside the field and isn't saved.
  • The file: its path is at the bottom, with Open config.toml and Show in folder. When the file can't be used, the page says why, and BeeZip uses the defaults until it's fixed.

Settings describes every setting.

Theme

Choose System (which follows Windows' light or dark mode), Light or Dark in Settings → Appearance, or from the palette's Theme: … actions, where the current one says current. Every BeeZip window switches at once, and BeeZip starts in that theme next time.

Updates

At most once a day, when it starts, BeeZip asks GitHub for its newest release. When there's a newer one, a banner below the tab strip names it, with What's new, which opens the release notes.

  • Update and restart downloads the new version, checks its signature against the release's version, and installs it; BeeZip restarts. Nothing downloads before you click. While jobs run, the button says Update when the jobs finish, and the update waits for them rather than cancelling them.
  • Not now (the ×) hides the banner until BeeZip starts again.
  • Check for updates in About BeeZip asks now, whatever the setting and however recently it last asked.
  • Turning it off: Settings → Updates → Look for updates.

The command line and the MCP server never check for updates.

The portable copy

A portable copy doesn't install updates. Its banner has Download instead of Update and restart, which opens the new zip in your browser. To update, close BeeZip and unzip the new version over the folder. If you added Explorer's menu from that copy, click Repair in Settings → Explorer menu afterwards; see Explorer's menu.

On Linux and macOS

The app is the same on Linux and macOS, with these differences:

  • No Explorer: there's no right-click menu, no job windows, and no dragging entries out to the file manager. Settings leaves out the Explorer menu and Job windows sections.
  • Opening archives: from the file manager's Open With on Linux, or Finder's Open With on macOS, for the archive types BeeZip registers. Opening another archive while BeeZip runs adds a tab to the running window, as on Windows.
  • Keys: on macOS, ⌘ works wherever this page says Ctrl.
  • The downloaded mark: on macOS, extracted files keep the archive's quarantine, as Archive Utility does, so macOS still checks an app that came in a download. Linux has no such mark, and Settings leaves the setting out there.
  • Settings are in ~/.config/BeeZip/config.toml on Linux and ~/Library/Application Support/BeeZip/config.toml on macOS.
