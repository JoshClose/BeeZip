AI assistants (MCP)

beezip mcp serves BeeZip's commands as MCP tools, so an assistant such as Claude can list, test, read, extract, create, change and convert archives. It writes only in the folders you name, and asks you, not the assistant, before it overwrites anything.

Setting it up

Give the assistant the full path to beezip and name the folders it may write to with --root. Without a root, it can read archives but can't extract, create or change anything.

Claude Code

claude mcp add beezip -- C:\path\to\beezip.exe mcp --root C:\Users\you\Unpacked
claude mcp add --scope user beezip -- C:\path\to\beezip.exe mcp --root C:\Users\you\Unpacked   # for every project

Claude Desktop

Open Settings → Developer → Edit Config, add BeeZip to claude_desktop_config.json, and restart Claude Desktop:

{
  "mcpServers": {
    "beezip": {
      "command": "C:\\path\\to\\beezip.exe",
      "args": ["mcp", "--root", "C:\\Users\\you\\Unpacked"]
    }
  }
}

Other clients

Any MCP client that starts servers over stdin and stdout works the same way: the command is beezip, and the arguments are mcp and your options. To try the tools by hand, use the MCP Inspector:

npx @modelcontextprotocol/inspector C:\path\to\beezip.exe mcp --root C:\tmp\sandbox

Where beezip is

  • Installed on Windows (from 1.0.0): %LOCALAPPDATA%\BeeZip\bin\beezip.exe.
  • The portable copy: bin\beezip.exe in its folder.
  • Linux: /usr/bin/beezip. macOS: /Applications/BeeZip.app/Contents/MacOS/bin/beezip.

Options

OptionWhat it does
--root DIRA folder BeeZip may write in. Repeat it for more. It replaces mcp.roots from the settings.
--read-onlyOffer only the tools that don't write.
--unrestrictedLet commands write anywhere. Use it only with a client you trust to ask you before every call.

The same can live in config.toml, so every client gets it (see Settings). The rest of your settings, such as levels, the overwrite choice and the limits, apply too.

[mcp]
roots = ['C:\Users\you\Unpacked']
read_only = false

The tools

ToolWritesWhat it does
formats_listThe formats and compressors BeeZip reads and writes.
file_detectWhat a file is: zstd → tar, a self-extracting archive, a split set, or not an archive.
archive_infoCounts, sizes, ratio, methods, encryption, volumes, and why it can't be changed, if it can't.
archive_listEntries, one folder level at a time or all of them, filtered and sorted.
archive_testReads everything back and checks it.
entry_readPart of one entry, as text, hex or base64.
archive_extractYesAll entries, or some, into a folder.
archive_createYesA new archive from files and folders, encrypted and split if asked.
archive_addYes, replacingFiles added to a zip, 7z, tar, cpio or ar.
archive_removeYes, replacingEntries removed.
archive_renameYes, replacingAn entry or folder renamed or moved.
archive_convertYesAny archive BeeZip reads, written as one it writes. The source stays.
stream_compressYesOne file through one compressor.
stream_decompressYesOne compression layer off a file.
bench_runThe compressors compared in memory. Nothing is written.
app_versionBeeZip's version.

The tools take the same arguments as the command line's commands; beezip schema command prints any of them. The tools that replace an archive are marked as destructive for clients that ask before such calls, and --read-only hides them.

Where it writes

  • Only under the roots. Every path a tool writes to is resolved first, following junctions and links, and one outside every root is refused.
  • Reads aren't confined: the assistant can open an archive anywhere you can.
  • Changing an archive rewrites it, so the archive itself must be under a root.
  • Paths should be absolute. A relative one is taken from the server's working folder, which depends on the client.
  • The settings are hidden from MCP clients, since one that could change the roots could widen its own sandbox.

Questions and passwords

  • Files already there: when no overwrite choice was given, BeeZip asks you through the client (replace, keep, keep both, for this file or all of them), where the client supports it. Elsewhere, the call fails and the assistant can retry with an overwrite choice.
  • Passwords are never asked for over MCP. An encrypted archive fails with PasswordRequired; the assistant asks you and calls again with the password. That means the password passes through the assistant, so only give it one you're willing to share there.

Limits

  • archive_list returns at most 500 entries per call; the assistant pages through the rest.
  • entry_read returns at most 256 KiB per call.
  • The zip-bomb limits in your settings apply as everywhere else.

Progress, cancelling and errors

  • Progress reaches clients that ask for it.
  • Cancelling a call cancels its job and removes its partly written file; so does the client disconnecting.
  • Errors come back with a stable code the assistant can act on: NotFound, InvalidArgs, UnsupportedFormat, UnsupportedOperation, PasswordRequired, WrongPassword, Corrupt, OutsideSandbox, Conflict, LimitExceeded, Unsafe, BackendUnavailable (only from a build without RAR), Cancelled, Io or Internal.
