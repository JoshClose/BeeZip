Formats

BeeZip reads archive formats and a dozen compressors, writes the common ones, and changes zip, 7z, tar, cpio and ar archives in place. This table comes from beezip formats, which shows the same on your machine.

Archives

Edit means adding, removing and renaming entries. Split means writing volumes (a.7z.001, a.7z.002…); BeeZip reads split archives of every kind.

How BeeZip recognises a file

BeeZip looks at what's inside a file, not at its name, so download.bin that's really a .tar.zst opens as one, and so does an archive with no extension at all. It unwraps compressors layer by layer (zstd → tar), and finds a self-extracting 7z, RAR, zip, CAB or LHA inside a program. beezip detect file says what it found, or what the file is when it isn't an archive.

Split archives

A split archive opens from any of its parts: a.7z.001, a.zip.001, a.part1.rar, a.rar with a.r00, a.arj with a.a01, and a.ace with a.c00. Spanned zips (a.z01) aren't read. BeeZip writes volumes in every format it writes; split archives can't be changed in place, so convert makes one file of them.

What to know about some formats

  • RAR (1.5 to 7) is read through UnRAR, whose license allows extracting RAR archives but not making them. A RAR whose entries have different passwords asks for each.
  • 7z and RAR 1.5 to 4 have no way to tell a wrong password from damage, so a wrong one shows as damaged data, and BeeZip asks again.
  • Zip encrypts with AES-256, or with ZipCrypto for old tools, which is weak. 7z encrypts with AES-256, and hides the file names too.
  • Debian packages list as dpkg-deb -R unpacks them: the files, and the control files under DEBIAN/. macOS packages list as pkgutil --expand-full unpacks them, with their Payload and Scripts as folders.
  • ISO images list their Rock Ridge, Joliet or plain names, or their UDF tree when it holds more (as Windows' own ISOs do). BeeZip writes ISO 9660 level 3, with Joliet and Rock Ridge. zisofs files are listed but not extracted, and El Torito boot images aren't listed.
  • DMG images (zlib, bzip2, LZFSE, LZMA, ADC or raw) list the HFS+, HFSX or APFS volume inside, or their partitions when there's no volume. Encrypted and sparse images aren't read. BeeZip writes an HFS+ volume in a zlib-compressed image.
  • squashfs reads every compressor (gzip, xz, lzma, lzo, lz4 and zstd), and writes gzip, xz, zstd, lz4 or lzo.
  • cpio reads every header format (newc, crc, odc and old binary) and writes newc, as initramfs images use. A file of 4 GiB or more doesn't fit.
  • ar and CAB hold files only, no folders. CAB reads none, MSZIP and LZX compression, and cabinet sets.
  • ARJ, ACE, ZOO and ARC come from the DOS days, with names in the OEM code page. ARJ's GOST40 encryption, ACE 2.0's special modes and PAK's crushed and distilled methods aren't read.
  • Compressed files on their own (.gz, .xz, .zst…) open as an archive of one file, and beezip decompress takes one layer off.

Disks, file systems and installers

BeeZip reads the virtual disks VHD, VHDX, VMDK, QCOW2 and VDI, GPT and MBR disks, FAT12, FAT16 and FAT32, NTFS, ext2/3/4, HFS+ and APFS volumes, and MSI installers, patches, transforms and merge modules itself, with no other program. It lists, tests and extracts them, and never changes them.

  • A virtual disk opens through its levels, such as VHDX › GPT › NTFS, and what's inside reads as below; a disk with nothing BeeZip reads inside is one file, name.img. BeeZip reads fixed, dynamic and differencing VHD and VHDX (4 KiB sectors too), VMDK's hosted, split, flat and stream-optimized disks and their snapshots, QCOW2 with its compressed clusters and backing files, and VDI's snapshots. A VHDX that Hyper-V left with writes pending in its log shows its latest contents: the log is applied in memory, never to the file.
  • A differencing disk's parent (or a snapshot's, or a backing file) is looked for by the path the disk records, then by its name beside the disk, then, for VHD, VHDX and VMDK, by its full path on a local drive. It must be the disk the child was made from: one changed since is refused, saying where BeeZip looked. A network or device path in a disk is never opened.
  • A disk with one partition opens straight into its file system. With several, each partition BeeZip reads is a folder named as 7-Zip names the partition (0.data), and the others are files of their sectors, which open in turn once extracted. Disks of 512-byte and 4 KiB sectors both read, and a GPT disk whose header is damaged reads from its backup at the disk's end.
  • NTFS, with clusters of up to 2 MiB, lists the system files under [SYSTEM], as 7-Zip does, alternate data streams as file:stream, a file's second name as a hard link, and symlinks and junctions as links. Compressed and sparse files read as they are, and so do files Windows compressed with CompactOS or compact /exe: (XPRESS and LZX), which 7-Zip extracts as zeros. Files encrypted with EFS, deduplicated, or compressed from a WIM elsewhere (WIMBoot) are listed, but BeeZip can't read them: extracting skips them, says why, and writes the rest.
  • ext2/3/4 lists hard links, links and special files. Names that aren't UTF-8 are read with Name encoding, and times keep their nanoseconds. A volume that wasn't cleanly unmounted shows its latest contents: its journal is applied in memory, never to the image.
  • FAT reads long names, and short ones in your system's OEM code page. Its times have no time zone, so they're shown as written. Info shows the volume's label.
  • HFS+ and APFS volumes read as the one in a DMG does: an HFS+ catalog in any number of pieces, as a long-used volume's is, and a sealed APFS volume, as macOS 11 and later's system volume is.
  • An MSI lists its files where they install, under Windows Installer's folder names (ProgramFiles64Folder/RustDesk/RustDesk.exe), with its custom-action DLLs and icons under [Binary] and [Icon]. Files the installer keeps outside itself are read from beside it, and each file is checked against the size and hash the installer records. Two files bound for the same place keep both: the second has its key before the extension. A cabinet that runs on into a second one inside the installer reads whole.
  • A merge module (.msm) lists its files where it puts them, as an MSI does (SystemFolder/vcruntime140.dll); those at the top go wherever the product that merges it chooses. Info gives the module's ID, version and language.
  • A patch or transform (.msp, .mst) lists its storages and streams as 7-Zip does: its tables (!File), its summary ([5]SummaryInformation), a patch's transforms as folders and its cabinets, named with .cab so they open as one. A patch's files are named by the installer it patches, which it doesn't hold, and most are changes only Windows Installer applies, so they're listed as the patch stores them. Info gives a patch's name and description and a transform's product codes. They store no checksums, so testing one shows that every stream can be read.
  • A sparse file that claims far more than the image holds, such as 100 GB in a few MiB, is refused by the ratio limit before anything is written, and so is a virtual disk's partition that claims far more than the disk's files hold.
  • What BeeZip doesn't read itself in a volume goes to 7-Zip when it's installed, and Info says so.

WIM and ESD images

BeeZip reads Windows' install images itself: WIM, ESD and split WIMs (.swm, opened from any part), stored or compressed with XPRESS, LZX or LZMS, solid or not. LZMS, which ESD images use, is decoded by Windows' own decoder, and on Linux and macOS by wimlib's library, which BeeZip loads when it's installed: apt install wimtools on Debian and Ubuntu, dnf install wimlib on Fedora, brew install wimlib on macOS (BeeZip's .deb and .rpm recommend it). Without it, opening an ESD says what to install.

  • Images are folders 1/, 2/, as 7-Zip names them; an image file with one image lists it at the top. Info gives the images' names.
  • Every file is checked against the SHA-1 the image records as it's read, and testing also checks the image's integrity table when it has one.
  • Hard links are listed as links, alternate streams as file:stream, and links and junctions as NTFS's are. A link Windows rewrote when it captured the image (a target inside the captured folder) points inside the image again.
  • Large images extract in parallel: chunks decode on every core, as [extract] threads allows. Chunks of up to 1 GiB, which wimlib writes on request, read within decoder_memory.

CHM help files

BeeZip reads compiled HTML Help files (.chm) itself, on every platform: it lists, tests and extracts them, and previews a page without decoding the rest. Installing BeeZip leaves .chm with Windows' help viewer, so a double-click still shows the help; BeeZip's items are in its right-click menu.

  • The listing is 7-Zip's: the help's pages, images and folders, and its own files (#SYSTEM, $OBJINST…). Info gives its title, language and compiler.
  • A CHM stores no checksums, so testing one shows that every file can be read, not that it's intact.
  • A file cut short still lists whole, and every file before the cut comes out; the rest are reported as cut short.
  • Layouts no compiler is known to write, which 7-Zip reads, read too: a compressed section under another name, and version 3 of its control data or reset table.

CramFS images

BeeZip reads CramFS, Linux's compressed ROM file system, itself, on every platform: it lists, tests and extracts an image, and reads one file without decoding the rest.

  • Every layout Linux reads: either byte order, blocks of 4 to 64 KiB (worked out from the image, which doesn't record them), holes, a 512-byte boot block before the image, and Linux 4.15's extended block pointers. 7-Zip reads none of these but the byte orders.
  • The listing is 7-Zip's: folders, files and links, with their permissions. CramFS stores no times. Devices, FIFOs and sockets are listed, and skipped when extracting.
  • Testing checks the image's CRC, and that every file decodes.
  • An image cut short still lists whole, and every file before the cut comes out; the rest are reported as cut short.
  • 7-Zip's own variant, which Linux doesn't read, reads too: LZMA or zlib, with blocks of 4 to 512 KiB.

NSIS installers

BeeZip reads NSIS installers itself, on every platform: from NSIS 2, Jim Park's Unicode NSIS and NSIS 3, 32- and 64-bit, solid or not, in zlib, bzip2 or LZMA. It lists, tests and extracts them, and never changes them.

  • The listing is 7-Zip's: files under $INSTDIR at the top, and those for other folders under the folder's name ($PLUGINSDIR/nsExec.dll, $SYSDIR/…). The uninstaller is listed as the installer writes it, even where 7-Zip leaves it out.
  • Sizes are exact. A solid installer is decoded once as it opens to find them, about as long as testing it with 7-Zip takes.
  • Testing checks the installer's CRC, and that every file decodes. An installer built with CRCCheck off has none to check.
  • An installer cut short still lists whole, and every file before the cut comes out; the rest are reported as cut short.
  • NSIS forks with first headers of their own (NSISBI's large installers, say) aren't recognised, by BeeZip or 7-Zip.

What goes through 7-Zip

With 7-Zip 25.01 or newer installed, BeeZip also lists, tests and extracts the few files of other formats that use something BeeZip doesn't read itself, such as an ext volume over 16 TiB.

  • 7-Zip only reads: every file streams from it through BeeZip's own extraction, with the same safety rules as every other format.
  • Finding 7-Zip: BeeZip looks in the registry, on PATH and in Program Files, or uses seven_zip.path in Settings. Without it, these formats are still recognised, and opening one says what to install.
  • Installing it: BeeZip doesn't come with 7-Zip. On Windows, Install 7-Zip beside the error, or in Settings → 7-Zip, installs it with winget, which downloads 7-Zip's own installer and checks its hash; Windows then asks for administrator rights, for 7-Zip's installer only. Update 7-Zip does the same for a 7-Zip older than 25.01. The file opens as soon as it's done, without restarting BeeZip; beezip 7zip install does the same from the command line. Without winget, and on Linux and macOS, Get 7-Zip… opens 7-Zip's download page. On Linux, take 7-Zip's own 7zz: distributions' packages are usually older than 25.01.
  • They're never changed: convert copies one into a format BeeZip writes.
