Formats

BeeZip reads archive formats and a dozen compressors, writes the common ones, and changes zip, 7z, tar, cpio and ar archives in place. This table comes from beezip formats, which shows the same on your machine.

Archives

Edit means adding, removing and renaming entries. Split means writing volumes (a.7z.001, a.7z.002…); BeeZip reads split archives of every kind.

How BeeZip recognises a file

BeeZip looks at what's inside a file, not at its name, so download.bin that's really a .tar.zst opens as one, and so does an archive with no extension at all. It unwraps compressors layer by layer (zstd → tar), and finds a self-extracting 7z, RAR, zip, CAB or LHA inside a program. beezip detect file says what it found, or what the file is when it isn't an archive.

Split archives

A split archive opens from any of its parts: a.7z.001, a.zip.001, a.part1.rar, a.rar with a.r00, a.arj with a.a01, and a.ace with a.c00. Spanned zips (a.z01) aren't read. BeeZip writes volumes in every format it writes; split archives can't be changed in place, so convert makes one file of them.

What to know about some formats

  • RAR (1.5 to 7) is read through UnRAR, whose license allows extracting RAR archives but not making them. A RAR whose entries have different passwords asks for each.
  • 7z and RAR 1.5 to 4 have no way to tell a wrong password from damage, so a wrong one shows as damaged data, and BeeZip asks again.
  • Zip encrypts with AES-256, or with ZipCrypto for old tools, which is weak. 7z encrypts with AES-256, and hides the file names too.
  • Debian packages list as dpkg-deb -R unpacks them: the files, and the control files under DEBIAN/. macOS packages list as pkgutil --expand-full unpacks them, with their Payload and Scripts as folders.
  • ISO images list their Rock Ridge, Joliet or plain names, or their UDF tree when it holds more (as Windows' own ISOs do). BeeZip writes ISO 9660 level 3, with Joliet and Rock Ridge. zisofs files are listed but not extracted, and El Torito boot images aren't listed.
  • DMG images (zlib, bzip2, LZFSE, LZMA, ADC or raw) list the HFS+, HFSX or APFS volume inside, or their partitions when there's no volume. Encrypted and sparse images aren't read. BeeZip writes an HFS+ volume in a zlib-compressed image.
  • squashfs reads every compressor (gzip, xz, lzma, lzo, lz4 and zstd), and writes gzip, xz, zstd, lz4 or lzo.
  • cpio reads every header format (newc, crc, odc and old binary) and writes newc, as initramfs images use. A file of 4 GiB or more doesn't fit.
  • ar and CAB hold files only, no folders. CAB reads none, MSZIP and LZX compression, and cabinet sets.
  • ARJ, ACE, ZOO and ARC come from the DOS days, with names in the OEM code page. ARJ's GOST40 encryption, ACE 2.0's special modes and PAK's crushed and distilled methods aren't read.
  • Compressed files on their own (.gz, .xz, .zst…) open as an archive of one file, and beezip decompress takes one layer off.

Formats read through 7-Zip

With 7-Zip 25.01 or newer installed, BeeZip also lists, tests and extracts the formats marked "Through 7-Zip" above: WIM and ESD images, CHM files, MSI and NSIS installers, and disk images and file systems, VHD, VHDX, VMDK, QCOW2 and VDI, GPT and MBR disks, FAT, NTFS, ext2/3/4, HFS+, APFS and CramFS.

  • 7-Zip only reads: every file streams from it through BeeZip's own extraction, with the same safety rules as every other format.
  • A disk opens through its levels, such as VHDX › GPT › NTFS; one with several partitions lists each as a file.
  • An MSI shows its files under the installer's internal names, as 7-Zip does.
  • Finding 7-Zip: BeeZip looks in the registry, on PATH and in Program Files, or uses seven_zip.path in Settings. Without it, these formats are still recognised, and opening one says what to install.
  • They're never changed: convert copies one into a format BeeZip writes.
