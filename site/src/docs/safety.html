Safety

An archive is someone else's idea of what should land on your disk. BeeZip checks every entry before it writes it, and tells you what it skipped. The same rules hold in the app, Explorer's menu, the command line and the MCP server.

Nothing lands outside the folder you chose

  • Paths that climb out, such as ../../Windows/evil.dll, are skipped.
  • Links that point out of the destination are skipped too, and so is anything that would be written through a link or junction leading out.
  • Devices, pipes and other special files aren't made.
  • The rest is extracted. Then the job ends with a report of what was skipped, and why; on the command line, with exit code 14.

Names Windows can't store

Absolute paths, drive letters, names Windows reserves (CON, NUL, COM1…) and characters it can't store are rewritten into names it can, and each rewrite is reported. Names that differ only in case, which Windows sees as one, are treated as one file: what to do with the second follows your choice for files already there.

Links

  • Symbolic links are off by default. Turned on (--links, the Extract dialog, or extract.links), BeeZip makes only links that stay inside the destination.
  • Hard links come out as copies of the file they point to.

Zip bombs

A zip bomb is a small archive that expands into something enormous. BeeZip never trusts the sizes an archive declares; it counts the bytes it actually produces.

  • The ratio: once an entry has produced 64 MiB, it may not grow past 10,000 times the compressed bytes it has read. One that does stops the job.
  • Entries: an archive may hold at most 10 million.
  • Memory: a decoder may use at most 1 GiB for its dictionary or window.
  • Everything: optionally, a cap on what one job writes in total.

Each can be changed in Settings. A job that reaches one fails saying which; on the command line, with exit code 11.

Mark of the Web

Windows marks files you download, and checks a marked program before it runs it. When you extract a downloaded archive, BeeZip gives every extracted file the archive's mark, as Explorer does, so a program inside is checked as if you'd downloaded it directly. Opening an entry from the app carries the mark too. On macOS, BeeZip copies the archive's quarantine instead, as Archive Utility does. extract.mark_of_the_web = "none" in Settings turns it off.

Changes never rewrite an archive in place

  • Adding, deleting and renaming write a new archive beside the old one and swap it in. A failed or cancelled change leaves the original as it was.
  • What the original had stays: its Mark of the Web, its hidden attribute and its creation time.
  • New archives are written to a temporary file and renamed into place, so a cancelled job leaves nothing behind.
  • Cancelling an extraction removes the file it was writing.

Encryption is never dropped quietly

  • Adding to an encrypted archive needs a password for the new files; adding them unencrypted takes a deliberate choice (--unencrypted).
  • Converting an encrypted archive needs a new password, or your explicit choice to decrypt it.
  • Passwords aren't saved. In the app, a password stays in memory for its tab, until you close it. Copy as CLI leaves it out.

For AI assistants

The MCP server adds rules of its own: an assistant may write only under the folders you name, never learns a password unless you give it one, and asks you, not itself, whether to overwrite a file. See AI assistants.
