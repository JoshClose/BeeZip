Explorer's menu

BeeZip adds a “BeeZip” submenu to Explorer's right-click menu, so you can extract, test and pack files without opening its window. This page lists what the menu offers for each kind of selection, what the small job windows do, how Windows 11's menu differs from the classic one, and how to install, change, repair and remove the menu.

What the menu offers

Right-click files or folders in Explorer, or on the desktop, and open BeeZip. On Windows 11 it's in Windows' own menu or under Show more options, depending on how BeeZip was installed; see Windows 11's menu and the classic menu.

The items

Settings and this page name the items for an archive called a.zip. In Explorer each title uses the names you selected.

Extract hereArchivesExtracts into the archive's own folder. When the archive holds more than one item at its top level, they go into a new folder named after it, so they don't spill out among your files.
Extract to "a\"ArchivesExtracts into a folder named after the archive, beside it.

Add to "a.zip"Any files and foldersPacks the selection into a zip beside it.

The archive items come first, then the add items. Every item shows unless you turn it off; see Choosing the items.

The add items use your levels from Settings → Compression levels, and the threads from Settings → Creating. Extracting from the menu follows Settings → Extracting, so with A file is already there set to Ask (the default), a file that's in the way brings up a question in the job window.

Which items a selection gets

  • Archives: when every selected item is a file BeeZip reads, you get every item. BeeZip goes by the name: .zip, .7z, .rar, .tar.zst, .gz and the rest, and the parts of split archives (.7z.001, .part2.rar, .r01…). Zip-based documents such as .jar, .docx and .epub count too, as do .iso and .cab, though double-clicking them still opens their usual apps.
  • Anything else: folders, files BeeZip doesn't read, or a mix of those and archives get the add items and Compress to….
  • Several archives: Extract to "a\" becomes Extract each to its own folder, Test archive becomes Test archives, and Extract to… isn't offered, since its dialog takes one archive. The parts of one split archive count as one: selecting a.7z.001 and a.7z.002 extracts the set once.
  • Several items for an add item: they all go into one archive.
  • Nothing: items with no place on disk, such as files inside a zip that Explorer opened as a folder, or on a phone, get no BeeZip items. Neither does the empty space in a folder.

How the items are named

  • Extract to "a\" uses the archive's name without its archive and compression extensions: photos.tar.zst gives photos\, backup.7z.001 gives backup\, music.part1.rar gives music\, and notes.txt.gz gives notes.txt\. Extract here's new folder, when it makes one, has the same name.
  • The add items name the new archive after one selected item: a file without its last extension (report.pdf gives Add to "report.zip"), an archive without its extensions (photos.tar.zst gives Add to "photos.zip"), or a folder by its name. Several items are named after the folder they're in, and the root of a drive gives archive. The new archive goes in the same folder as the selection.
  • Long names are cut, ending in “…”, so a title is at most 40 characters. The file BeeZip writes has the full name.

Job windows

Extract here, Extract to "a\", Test archive and the add items open a small BeeZip window for the job. Open with BeeZip, Extract to… and Compress to… open BeeZip's main window instead, or use the one that's already open, with no job window.

When BeeZip is already running, the job goes to it, and it opens the job window. Each click gets a window of its own, and they run side by side.

What a job window shows

  • While it runs: what it's doing (“Extracting photos.zip”), also in the window's title bar; a progress bar with how much is done out of the total, the speed and the time left; and the file being worked on.
  • Several archives: they're done one after another, and the window counts them: “2 of 5”.
  • Cancel stops the job, removes any files it had started writing, and skips the archives left.
  • When it ends: each archive's result, such as “Extracted 214 files, 18 MiB, to C:\Users\you\Downloads\photos” or “All 214 entries are OK (18 MiB read)”, or its error. Open folder shows what was written in Explorer: the new folder or archive, or the archive itself when its files went beside it. A job that skipped unsafe entries has Show report, as in the desktop app. Close closes the window.
  • Missing files: an item that has gone since you right-clicked fails on a line of its own, and the rest still run.

Closing a job window while its job runs asks first: Cancel and close, or Keep working.

Passwords and existing files

A job window asks the desktop app's questions, and grows to fit them:

  • Password needed, for an encrypted archive. BeeZip uses the password for this job only, and never saves it.
  • A file with this name exists, when extracting meets a file that's in the way: Replace, Replace all, Skip, Skip all, Keep both or Cancel. See Files that are already there.

When the archive is already there

When Add to "a.zip" finds an a.zip already in the folder, the job window asks “a.zip is already there” before it writes anything:

  • Add to it adds the selection to that archive, at its top level. An entry that's already in it brings up a question (“notes.txt is already in a.zip”), and an encrypted archive asks for the new files' password. This choice comes first, and only for an archive BeeZip can edit; see What can't be edited.
  • Replace writes a new a.zip in its place.
  • Keep both writes the new archive beside it, under the first free name: a (1).zip, a (2).zip…
  • Skip leaves the archive as it was, and writes nothing.

Closing when done

After a success where nothing was skipped or renamed, the job window says Closing… and closes itself two seconds later. After anything else, such as an error, a cancel, or files skipped or renamed, it stays until you close it, so you can read what happened.

To keep every job window open, turn off Close the window after a success where nothing was skipped or renamed in Settings → Job windows, or set it in config.toml:

[jobs]
close_when_done = false

Windows 11's menu and the classic menu

Windows 11 has two right-click menus: its own, and the classic one, which it shows under Show more options. Windows 10 has only the classic one.

  • Windows 11's own menu needs BeeZip's signed package. It comes with the signed installer, from version 1.0.0. There, BeeZip is always a submenu.
  • The classic menu is what the portable copy and unsigned builds register. On Windows 11 you find BeeZip under Show more options; on Windows 10 it's in the menu itself. Here BeeZip can be a submenu or put its items at the top of the menu.
  • Only one at a time: registering one kind takes the other away, so BeeZip never shows twice.

Before 1.0.0 the portable copy is BeeZip's only Windows download, so for now BeeZip is under Show more options on Windows 11. Settings → Explorer menu says which menu you have.

On an installed BeeZip with Windows' Developer Mode on, beezip shell install --mode modern --dev moves the menu into Windows 11's own menu without a signed package, and beezip shell install --mode classic moves it back.

Installing, repairing and removing it

The menu is registered for your Windows account only, and needs no administrator rights. The installer adds it without asking, and uninstalling BeeZip removes it, along with BeeZip's other registrations.

From Settings

Settings → Explorer menu shows what's registered now:

  • Not installed, with Install;
  • Installed: a "BeeZip" submenu or Installed: items at the top level (the classic menu), or Installed: Windows 11's menu, with Repair and Remove.

Anything wrong with the registration, such as a missing file or both kinds of menu at once, is listed in red below that line. Each button asks before it changes Explorer.

  • Install registers the best menu this Windows can have from this copy of BeeZip. On Windows 11, when that can't be Windows' own menu, it says why below the buttons.
  • Repair registers the same kind of menu again, pointing it at the BeeZip you're running. It fixes a menu that has stopped working.
  • Remove takes BeeZip out of the menu. Your choice of items stays, for when you install it again.

From the command line

beezip shell status       # which menu is registered, and anything wrong with it
beezip shell install      # add the menu, or repair it
beezip shell uninstall    # remove it

beezip shell install picks the menu as Install does; --mode classic or --mode modern asks for one. Running it again repairs the menu. beezip shell uninstall leaves your settings alone. See The command line.

The portable copy

The portable copy installs nothing on its own: add the menu from Settings → Explorer menu → Install. It registers the classic menu.

The menu runs BeeZip from the portable copy's folder. Remove the menu before you move or delete that folder, or the menu is left pointing at files that aren't there.

  • After moving the folder: run BeeZip from its new place and click Repair.
  • After updating: when you unzip a new version over the folder, click Repair afterwards.
  • If the folder is already gone: run any copy of BeeZip and click Remove, or Repair to point the menu at that copy.

Choosing the items

Settings → Explorer menu has a checkbox for each item, under Items, and Show the items in a "BeeZip" submenu, under Layout. Turning the submenu off puts each item at the top of the classic menu, with BeeZip's icon. Windows 11's own menu always shows a submenu, so the setting is greyed out there. A change reaches the menu at once.

Both are in config.toml, under [shell]:

[shell]
cascade = true             # classic menu: false puts each item at the top level
[shell.items]              # every item shows unless set to false
test = false
add-tar-zst = false

The items' keys are open, extract-here, extract-folder, extract-to, test, add-zip, add-7z, add-tar-zst and compress-to. The command line sets them too:

beezip settings set shell.items.test=false shell.cascade=false

Settings lists every setting.

Troubleshooting

  • BeeZip isn't in Windows 11's menu: look under Show more options. Without the signed package, that's where BeeZip goes; see above.
  • The menu stopped working, or a click does nothing: click Repair in Settings → Explorer menu, or run beezip shell install. Anything listed in red there says what was wrong.
  • You moved or updated a portable copy: click Repair from the copy you now use.
  • Only the add items show: the selection includes a folder, or a file BeeZip doesn't read by its name.
  • Extract to… is missing: more than one archive is selected. It takes one.
  • No BeeZip at all: check that the menu is installed, in Settings → Explorer menu, and that the items you want are ticked. Items inside a zip that Explorer opened as a folder, or on a phone, never get BeeZip's menu.
  • A job window keeps asking about existing files: choose another answer for A file is already there in Settings → Extracting.
