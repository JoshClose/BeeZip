The command line

beezip does everything the app does, from a terminal or a script, with the same settings and the same safety rules. This page walks through the everyday commands; the command reference lists every option of every one.

The basics

Every command is beezip command followed by its arguments. The common ones have short aliases:

CommandAliasWhat it does
listlLists what's inside
extractxExtracts all of it, or some
createcMakes a new archive
testtReads everything back and checks it
addaAdds files to an archive
removedRemoves entries from an archive
renamernRenames or moves an entry
  • Help: beezip --help lists the commands, and beezip command --help explains one.
  • Formats are recognised by content: BeeZip looks inside a file to see what it is, so an archive with the wrong extension, or none, still opens. beezip detect file says what it found.
  • Any part of a split archive opens the whole set: beezip x big.7z.002 works.
  • Defaults come from config.toml, and options override them. See Settings.

Looking inside an archive

beezip info backup.tar.zst              # entries, sizes, ratio, methods, encryption
beezip list backup.zip                  # the top folder: one level at a time
beezip list backup.zip docs             # the docs folder
beezip list backup.zip --flat           # every entry
beezip list backup.zip --glob "*.md"    # every entry matching a pattern
beezip list photos.rar --sort size --reverse --kind file
beezip read backup.zip docs/a.md        # print part of an entry
beezip read backup.zip app.bin --encoding hex --max-bytes 256
beezip test backup.zip                  # read it all back, checking CRCs
  • list shows one folder level unless you pass --flat or a --glob. Folders come first; --sort takes another column and --kind shows only files or folders.
  • Patterns: without a /, a pattern matches a name at any depth (*.txt); with one, the whole path (docs/**/*.md).
  • read prints part of one entry without extracting it, as text, hex or base64, from --offset for up to --max-bytes.
  • test fails with exit code 8 when an entry is damaged, and names it.
  • detect says what a file is: zstd → tar, a self-extracting zip, a split set, or "not an archive" and what it is instead.
  • formats lists every format and compressor, with what BeeZip does with each, its methods and levels.

Extracting

beezip x backup.zip                     # into the current folder
beezip x backup.zip -o out              # into out
beezip x backup.zip docs readme.txt     # just these (a folder takes all it holds)
beezip x backup.zip --glob "*.jpg" -o photos
beezip x backup.zip --smart             # into a folder named after the archive, if it
                                        # holds more than one item, as Extract here does
beezip x release.tar.gz --strip-components 1
beezip x backup.zip --overwrite rename --dry-run
  • Files already there: BeeZip asks, in a terminal. --overwrite decides instead: always, never, rename (writes name (1).ext) or newer (replaces only older files).
  • --dry-run shows what would be extracted, and where, without writing anything.
  • --exclude leaves out entries matching a pattern; repeat it for more.
  • Symbolic links aren't made unless you pass --links, and then only ones that stay inside the destination. Hard links come out as copies.
  • Unsafe entries, such as paths climbing out with .., are skipped. The rest is extracted, and the command ends with exit code 14, listing what it skipped. See Safety.
  • Mark of the Web: on Windows, files from a downloaded archive keep its mark, as Explorer does. [extract] mark_of_the_web in Settings changes that.

Creating archives

beezip c backup.tar.zst src -l 19          # the format comes from the extension
beezip c backup.zip src docs readme.md     # several inputs
beezip c secret.zip src -p "pass phrase"   # AES-256
beezip c old-tools.zip src -p "pass phrase" --encryption zipcrypto
beezip c logs.zip logs -m ppmd --exclude "*.tmp"
beezip c backup.7z src -p "pass phrase"    # the names are encrypted too
beezip c big.7z videos -v 4g --solid=false # big.7z.001, big.7z.002…
beezip c initrd.cpio.gz rootfs
beezip c drivers.cab inf -m mszip
beezip c disc.iso photos                   # ISO 9660 with Joliet and Rock Ridge
beezip c rootfs.squashfs rootfs -m zstd
beezip c app.dmg build/App                 # an HFS+ volume in a compressed image
beezip c project.bhive src                 # BeeZip's own format
beezip c project.bhive src -l max          # none, fast, balanced, high or max
  • Each input keeps its own name: src goes in as src/….
  • The format comes from the output's extension (.zip, .bhive, .7z, .tar, .tar.zst, .tgz, .cpio.gz, .ar, .cab, .iso, .squashfs, .dmg…), or from -f.
  • Methods with -m: for zip, store, deflate (the default), bzip2, zstd, xz or ppmd; for 7z, lzma2 (the default), lzma, ppmd, bzip2, deflate or copy; for CAB, mszip or store; for squashfs, gzip, xz, zstd, lz4 or lzo. A tar's compressor comes from its extension.
  • Levels with -l: each compressor has its own range; beezip formats shows them, and [levels] in Settings sets your defaults. A .bhive has five, by number or by name: -l 0 to 4, or none, fast, balanced (the default), high and max. It takes no -m.
  • Encryption: zip, 7z and .bhive, with -p. Zip uses AES-256 unless you ask for --encryption zipcrypto, which is weak but opens in old tools. A 7z with a password encrypts its file names too, unless --encrypt-headers=false. A .bhive hides everything, and takes other ways in besides a password: see Encrypted and signed .bhive.
  • Solid 7z compresses files together, which is smaller but slower to read one file from. It's on unless --solid=false.
  • Volumes with -v: a size such as 100m, 4g or 700MB (powers of 1024), in every format. The parts are name.001, .002…
  • Threads: --threads 0 uses every core, for the compressors that can.
  • Nothing half-written: the archive is written to a temporary file and renamed into place, so a failed or cancelled job leaves nothing behind.

Changing an archive

beezip add backup.zip notes.txt --dir docs   # into docs/, made if it isn't there
beezip add backup.7z new-photos              # a folder and all it holds
beezip remove backup.zip docs/old.txt        # an entry
beezip remove backup.7z --glob "*.tmp" --dry-run
beezip rename backup.zip docs papers         # a folder and everything in it
beezip rename backup.zip a.txt notes/a.txt   # renaming can move, too
  • Which archives: zip, .bhive, 7z, tar, cpio and ar, and tar and cpio under any compressor. Others (RAR, CAB, the disk images, packages, split and self-extracting archives) can't be changed; convert makes one that can.
  • Entries already there: add asks, or follows --overwrite.
  • Encrypted archives: adding to one needs -p for the new files, or --unencrypted to add them in the clear. An encrypted .bhive keeps its key and its ways in: -p, or one of your keys, is the way in, and the new files are sealed with the rest.
  • Signed .bhive archives lose their signatures when their files change, and BeeZip says so first. add --sign signs again as it adds; after a removal or a rename, beezip sign does.
  • Nothing is changed in place: a new archive is written beside the old one and swapped in, so a failed or cancelled change leaves it as it was. What stays is copied without being compressed again.
  • --dry-run shows each change without making it.

Converting

beezip convert old.rar new.7z               # any archive BeeZip reads, as one it writes
beezip convert a.tar.gz a.tar.zst           # entries copied, the stream compressed again
beezip convert disk.vhdx files.zip          # a disk image's files, as a zip
beezip convert secret.7z open.zip --decrypt # encryption is only dropped when you say so
beezip convert secret.7z secret.zip -p old --new-password new
beezip convert secret.zip for-bob.bhive -p old --to bob

The source isn't changed. What the new format can't hold is left out and reported. Entries are copied without decoding when the formats match and no option asks otherwise. An encrypted .bhive converted into a .bhive keeps its ways in unless you give it new ones, and a signed one keeps its signatures as long as its entries stay as they were. Choosing entries, a level or another format drops them, and BeeZip says so first.

Encrypted and signed .bhive

A .bhive can have any number of ways in, and any one opens it. These options are for a .bhive only, on create and convert; the command reference has every option of the commands below.

beezip c secret.bhive src -p "pass phrase"          # names, dates and folders sealed too
beezip c secret.bhive src -p "pass phrase" --strength strong
beezip c vault.bhive docs -p "pass phrase" --recovery-key   # shown once: keep it safe
beezip c team.bhive src --to age1pq1… --to bob      # public keys, or contacts by name
beezip c work.bhive src --to-cert alice.cer         # a certificate file, or a thumbprint
beezip c here.bhive src --this-pc --recovery-key    # This PC needs another way in
beezip c key.bhive src --security-key -p "pass phrase"
  • A password (-p, or --password-stdin to read it from the first line of stdin, where other programs can't see it) goes through Argon2id: --strength standard, the default, takes 1 GiB of memory and 2 passes, about 0.3 s on a fast desktop and 0.6 s on a laptop; strong takes 2 GiB and 3 passes. Opening one that needs more than half the machine's memory asks first.
  • --recovery-key makes 48 digits that open the archive when every other way in is lost. create, convert and protect print it once, and BeeZip never keeps it.
  • --to takes public keys in age's format, age1pq1… (post-quantum) or age1… (classic), or the name of one of your keys or contacts. A key from age-keygen works.
  • --to-cert takes an RSA (2,048 bits or more) or EC (P-256, P-384) certificate: a thumbprint in your stores (beezip certificates list shows them), or a .cer, .crt, .der or .pem file. One that can't be used is refused, saying why; an expired one gets a warning.
  • On Windows, --this-pc puts a key in the PC's TPM (--this-pc-pin guards it with a PIN), --security-key lets a FIDO2 security key open it, and --windows-hello Windows Hello. This PC and Windows Hello work only on that PC, so BeeZip won't make an archive they alone open. Security keys and smart cards haven't been tried on a physical device yet.
  • A password beside someone else's key or certificate gets a warning: anyone who can open the archive could make one your password opens. --sign shows which one you made. One of your own keys beside it doesn't count: you hold both.

Opening one

beezip x secret.bhive -o out                        # asks, in a terminal
beezip x secret.bhive -o out -p "pass phrase"       # the password, or the recovery key
beezip x team.bhive -o out -i my-key.txt            # a key file
beezip protection secret.bhive                      # its ways in, and whether it resists quantum computers
  • Your own keys (below) open an archive without asking. So do the key files -i names (age identities, PEM and PKCS #8 keys, and .pfx and .p12 files on Windows and macOS; on Linux, a .pfx is refused, with the openssl pkcs12 command that turns it into a PEM file), and on Windows the certificates in your stores and This PC, as long as they don't need a PIN.
  • In a terminal, BeeZip otherwise asks: the password, the recovery key, or a key or device it has that fits, which Windows then asks a PIN or a touch for. A device is used only when you choose it. A This PC key with a PIN is the exception: BeeZip asks for its PIN itself, with a hidden prompt. Windows blocks the TPM for a few hours after several wrong PINs, so if you're not sure of it, open the archive another way.
  • Without a terminal, an archive a password or recovery key opens fails with exit code 6, as a zip does, saying to pass -p; one that only keys or devices open fails with exit code 15, saying to pass -i. A wrong password is exit code 7.

Changing who can open it

beezip protect secret.bhive --to bob                # add a way in
beezip protect secret.bhive --add-password "another" --recovery-key
beezip protect secret.bhive --remove 1              # by its number in beezip protection
beezip protect secret.bhive --new-key --add-password "pass phrase"
  • Nothing is recompressed. Adding and removing keep the archive's key; the last way in that works on another machine can't go.
  • Removing isn't revoking: someone who opened the archive before could have kept its key. --new-key shuts them out of later versions: it seals every cell again and rebuilds every way in. A password can't be read back, so the archive's password needs --add-password (it, or a new one: the new key has one) or --remove; the recovery key is new, and a security key needs a touch.
  • What the archive says of its ways in (the labels and keys protection lists) could have been changed by anyone who opened it. So --new-key rebuilds a key or certificate that isn't yours or a contact's only when --confirm N names it: check it first.

Keys

beezip keys create me                               # post-quantum, to open archives
beezip keys create me-sig --kind signing            # to sign them
beezip keys export me                               # the public key, to share
beezip keys import bob --text age1pq1…              # a contact; --file for a key file or certificate
beezip keys list
beezip certificates list                            # what your certificates can do here
  • Your keys are post-quantum by default (age1pq1…), or --kind classic (age1…) for older age tools, or --kind signing (bzsig1…). The private key stays on this machine, in a keys folder beside config.toml, sealed by the system: by Windows for your account, in the login Keychain on macOS, in a file only you can read on Linux.
  • keys export --secret prints the private key, for a backup. Anyone who has it can open what it opens, or sign as you.
  • Contacts are other people's public keys (age1…, age1pq1…, bzsig1…) and certificates, by name, for --to and --require-signer. Importing a private key makes it yours.

Signatures

beezip c release.bhive dist --sign me-sig           # your signing key, by name
beezip c release.bhive dist --sign alice.pfx        # or a certificate: a thumbprint, a file, a .pfx
beezip sign old.bhive --sign me-sig                 # sign an archive already made
beezip sign old.bhive --remove 1                    # by its number in beezip info; --remove-all
beezip verify release.bhive                         # signed by you, a contact or a trusted certificate?
beezip x release.bhive -o out --require-signer alice
  • A signature covers the contents: changing who can open the archive, a new key, or encrypting it keeps it. add, remove and rename drop it, and say so first; add --sign signs again, and so does beezip sign afterwards.
  • info and test show each signature, numbered from 1, with its signer (you, a contact, a certificate the system trusts, or unknown) and its 16-character fingerprint. The time it gives is the signer's claim.
  • A signature that fails (the archive changed after it was signed) is a warning: the archive still opens. verify fails, with exit code 16, unless no signature failed and one is valid from someone you trust, or from each --require-signer.
  • --require-signer, on extract, test and verify, takes a bzsig1… key, a certificate file, or a signing key's or contact's name, and matches its whole SHA-256, never the fingerprint. extract checks before it writes anything.

Compressing single files

beezip compress big.log -c xz -l 9      # big.log.xz; big.log stays
beezip compress big.log                 # with the default compressor, zstd
beezip decompress backup.tar.zst        # backup.tar: one layer each time

The output keeps the input's modification time. [stream] codec in Settings sets the default compressor.

Opening an entry

beezip open backup.zip docs/report.pdf

The entry is extracted, with the archive's Mark of the Web, into a folder of its own under %TEMP%\BeeZip\open, and opened with its app. Folders there older than a day are cleaned up as BeeZip goes.

Passwords and questions

  • In a terminal, BeeZip asks for a password when an archive needs one, and what to do with a file that's already there.
  • An encrypted .bhive asks for one of its ways in: the password, the recovery key, or a key or device BeeZip has that fits. See Opening one.
  • Without a terminal, as in a script, it fails instead, and says which option to pass: --password (or --password-stdin), --identity or --overwrite.
  • 7z and old RAR archives can't tell a wrong password from damage, so a wrong one shows as damaged data. BeeZip asks again, up to three times. A RAR whose entries have different passwords asks for each.
  • On a shared machine, a password on the command line can show up in the shell's history; let BeeZip ask instead, or pass it on stdin with --password-stdin.

Names from other systems

Older zips and many other formats store names as bytes, in whatever code page their system used. BeeZip reads them as UTF-8, and otherwise as Windows' own code page. When names come out garbled, name the code page they were written in:

beezip list old.zip --name-encoding cp932     # Japanese Windows
beezip x old.zip --name-encoding cp866        # Russian DOS

beezip list --help lists every code page BeeZip knows, and [names] encoding in Settings sets a default.

Output for scripts

beezip list backup.zip --flat --output json
beezip x backup.zip -o out --output ndjson
beezip x backup.zip -o out -q
  • --output json prints one JSON document: the result, or {"error": {…}}.
  • --output ndjson streams every event as a line of JSON, progress included, ending with Finished, Failed or Cancelled.
  • -q hides progress bars and information; warnings still print.
  • Ctrl+C cancels and removes the partly written file. A second Ctrl+C exits at once, and still removes it.

Exit codes

CodeMeaning
0It worked
2An argument wasn't valid
3Something wasn't found: the archive, or an entry
4The format isn't supported
6A password is needed, or an encrypted .bhive's recovery key
7The password is wrong
8The archive is damaged
10A file is already there, and nobody could be asked
11A limit was reached, such as the zip-bomb ratio
13Reading or writing a file failed
14Unsafe entries were skipped; the rest was extracted
15An encrypted .bhive that only keys, certificates or devices open, and none given does: pass its key file
16The .bhive isn't signed as verify or --require-signer asks
130Cancelled

Any command, by name

The desktop app and the MCP server call BeeZip's commands by name, with JSON arguments. The command line can too, which helps when a script builds the arguments:

beezip commands                                        # every command
beezip schema archive.extract                          # its input and output schemas
beezip run archive.list --json '{"archive": "a.zip"}'

Comparing compressors

beezip bench                              # the common ones, on BeeZip's own sample
beezip bench big.iso --grid full          # every compressor at every level, on a file
beezip bench -g zstd:3,zstd:19:0,xz:6     # compressor[:level[:threads]]

Each compressor packs and unpacks a sample in memory, and reports the size, the speed and the memory each way. Every round trip is checked against the sample. Nothing is written.
