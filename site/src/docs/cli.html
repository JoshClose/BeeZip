The command line

beezip does everything the app does, from a terminal or a script, with the same settings and the same safety rules. This page walks through the everyday commands; the command reference lists every option of every one.

The basics

Every command is beezip command followed by its arguments. The common ones have short aliases:

CommandAliasWhat it does
listlLists what's inside
extractxExtracts all of it, or some
createcMakes a new archive
testtReads everything back and checks it
addaAdds files to an archive
removedRemoves entries from an archive
renamernRenames or moves an entry
  • Help: beezip --help lists the commands, and beezip command --help explains one.
  • Formats are recognised by content: BeeZip looks inside a file to see what it is, so an archive with the wrong extension, or none, still opens. beezip detect file says what it found.
  • Any part of a split archive opens the whole set: beezip x big.7z.002 works.
  • Defaults come from config.toml, and options override them. See Settings.

Looking inside an archive

beezip info backup.tar.zst              # entries, sizes, ratio, methods, encryption
beezip list backup.zip                  # the top folder: one level at a time
beezip list backup.zip docs             # the docs folder
beezip list backup.zip --flat           # every entry
beezip list backup.zip --glob "*.md"    # every entry matching a pattern
beezip list photos.rar --sort size --reverse --kind file
beezip read backup.zip docs/a.md        # print part of an entry
beezip read backup.zip app.bin --encoding hex --max-bytes 256
beezip test backup.zip                  # read it all back, checking CRCs
  • list shows one folder level unless you pass --flat or a --glob. Folders come first; --sort takes another column and --kind shows only files or folders.
  • Patterns: without a /, a pattern matches a name at any depth (*.txt); with one, the whole path (docs/**/*.md).
  • read prints part of one entry without extracting it, as text, hex or base64, from --offset for up to --max-bytes.
  • test fails with exit code 8 when an entry is damaged, and names it.
  • detect says what a file is: zstd → tar, a self-extracting zip, a split set, or "not an archive" and what it is instead.
  • formats lists every format and compressor, with what BeeZip does with each, its methods and levels.

Extracting

beezip x backup.zip                     # into the current folder
beezip x backup.zip -o out              # into out
beezip x backup.zip docs readme.txt     # just these (a folder takes all it holds)
beezip x backup.zip --glob "*.jpg" -o photos
beezip x backup.zip --smart             # into a folder named after the archive, if it
                                        # holds more than one item, as Extract here does
beezip x release.tar.gz --strip-components 1
beezip x backup.zip --overwrite rename --dry-run
  • Files already there: BeeZip asks, in a terminal. --overwrite decides instead: always, never, rename (writes name (1).ext) or newer (replaces only older files).
  • --dry-run shows what would be extracted, and where, without writing anything.
  • --exclude leaves out entries matching a pattern; repeat it for more.
  • Symbolic links aren't made unless you pass --links, and then only ones that stay inside the destination. Hard links come out as copies.
  • Unsafe entries, such as paths climbing out with .., are skipped. The rest is extracted, and the command ends with exit code 14, listing what it skipped. See Safety.
  • Mark of the Web: on Windows, files from a downloaded archive keep its mark, as Explorer does. [extract] mark_of_the_web in Settings changes that.

Creating archives

beezip c backup.tar.zst src -l 19          # the format comes from the extension
beezip c backup.zip src docs readme.md     # several inputs
beezip c secret.zip src -p "pass phrase"   # AES-256
beezip c old-tools.zip src -p "pass phrase" --encryption zipcrypto
beezip c logs.zip logs -m ppmd --exclude "*.tmp"
beezip c backup.7z src -p "pass phrase"    # the names are encrypted too
beezip c big.7z videos -v 4g --solid=false # big.7z.001, big.7z.002…
beezip c initrd.cpio.gz rootfs
beezip c drivers.cab inf -m mszip
beezip c disc.iso photos                   # ISO 9660 with Joliet and Rock Ridge
beezip c rootfs.squashfs rootfs -m zstd
beezip c app.dmg build/App                 # an HFS+ volume in a compressed image
  • Each input keeps its own name: src goes in as src/….
  • The format comes from the output's extension (.zip, .7z, .tar, .tar.zst, .tgz, .cpio.gz, .ar, .cab, .iso, .squashfs, .dmg…), or from -f.
  • Methods with -m: for zip, store, deflate (the default), bzip2, zstd, xz or ppmd; for 7z, lzma2 (the default), lzma, ppmd, bzip2, deflate or copy; for CAB, mszip or store; for squashfs, gzip, xz, zstd, lz4 or lzo. A tar's compressor comes from its extension.
  • Levels with -l: each compressor has its own range; beezip formats shows them, and [levels] in Settings sets your defaults.
  • Encryption: zip and 7z, with -p. Zip uses AES-256 unless you ask for --encryption zipcrypto, which is weak but opens in old tools. A 7z with a password encrypts its file names too, unless --encrypt-headers=false.
  • Solid 7z compresses files together, which is smaller but slower to read one file from. It's on unless --solid=false.
  • Volumes with -v: a size such as 100m, 4g or 700MB (powers of 1024), in every format. The parts are name.001, .002…
  • Threads: --threads 0 uses every core, for the compressors that can.
  • Nothing half-written: the archive is written to a temporary file and renamed into place, so a failed or cancelled job leaves nothing behind.

Changing an archive

beezip add backup.zip notes.txt --dir docs   # into docs/, made if it isn't there
beezip add backup.7z new-photos              # a folder and all it holds
beezip remove backup.zip docs/old.txt        # an entry
beezip remove backup.7z --glob "*.tmp" --dry-run
beezip rename backup.zip docs papers         # a folder and everything in it
beezip rename backup.zip a.txt notes/a.txt   # renaming can move, too
  • Which archives: zip, 7z, tar, cpio and ar, and tar and cpio under any compressor. Others (RAR, CAB, the disk images, packages, split and self-extracting archives) can't be changed; convert makes one that can.
  • Entries already there: add asks, or follows --overwrite.
  • Encrypted archives: adding to one needs -p for the new files, or --unencrypted to add them in the clear.
  • Nothing is changed in place: a new archive is written beside the old one and swapped in, so a failed or cancelled change leaves it as it was. What stays is copied without being compressed again.
  • --dry-run shows each change without making it.

Converting

beezip convert old.rar new.7z               # any archive BeeZip reads, as one it writes
beezip convert a.tar.gz a.tar.zst           # entries copied, the stream compressed again
beezip convert disk.vhdx files.zip          # a disk image's files, as a zip
beezip convert secret.7z open.zip --decrypt # encryption is only dropped when you say so
beezip convert secret.7z secret.zip -p old --new-password new

The source isn't changed. What the new format can't hold is left out and reported. Entries are copied without decoding when the formats match and no option asks otherwise.

Compressing single files

beezip compress big.log -c xz -l 9      # big.log.xz; big.log stays
beezip compress big.log                 # with the default compressor, zstd
beezip decompress backup.tar.zst        # backup.tar: one layer each time

The output keeps the input's modification time. [stream] codec in Settings sets the default compressor.

Opening an entry

beezip open backup.zip docs/report.pdf

The entry is extracted, with the archive's Mark of the Web, into a folder of its own under %TEMP%\BeeZip\open, and opened with its app. Folders there older than a day are cleaned up as BeeZip goes.

Passwords and questions

  • In a terminal, BeeZip asks for a password when an archive needs one, and what to do with a file that's already there.
  • Without a terminal, as in a script, it fails instead, and says which option to pass: --password or --overwrite.
  • 7z and old RAR archives can't tell a wrong password from damage, so a wrong one shows as damaged data. BeeZip asks again, up to three times. A RAR whose entries have different passwords asks for each.
  • On a shared machine, a password on the command line can show up in the shell's history; let BeeZip ask instead.

Names from other systems

Older zips and many other formats store names as bytes, in whatever code page their system used. BeeZip reads them as UTF-8, and otherwise as Windows' own code page. When names come out garbled, name the code page they were written in:

beezip list old.zip --name-encoding cp932     # Japanese Windows
beezip x old.zip --name-encoding cp866        # Russian DOS

beezip list --help lists every code page BeeZip knows, and [names] encoding in Settings sets a default.

Output for scripts

beezip list backup.zip --flat --output json
beezip x backup.zip -o out --output ndjson
beezip x backup.zip -o out -q
  • --output json prints one JSON document: the result, or {"error": {…}}.
  • --output ndjson streams every event as a line of JSON, progress included, ending with Finished, Failed or Cancelled.
  • -q hides progress bars and information; warnings still print.
  • Ctrl+C cancels and removes the partly written file. A second Ctrl+C exits at once, and still removes it.

Exit codes

CodeMeaning
0It worked
2An argument wasn't valid
3Something wasn't found: the archive, or an entry
4The format isn't supported
6A password is needed
7The password is wrong
8The archive is damaged
10A file is already there, and nobody could be asked
11A limit was reached, such as the zip-bomb ratio
13Reading or writing a file failed
14Unsafe entries were skipped; the rest was extracted
130Cancelled

Any command, by name

The desktop app and the MCP server call BeeZip's commands by name, with JSON arguments. The command line can too, which helps when a script builds the arguments:

beezip commands                                        # every command
beezip schema archive.extract                          # its input and output schemas
beezip run archive.list --json '{"archive": "a.zip"}'

Comparing compressors

beezip bench                              # the common ones, on BeeZip's own sample
beezip bench big.iso --grid full          # every compressor at every level, on a file
beezip bench -g zstd:3,zstd:19:0,xz:6     # compressor[:level[:threads]]

Each compressor packs and unpacks a sample in memory, and reports the size, the speed and the memory each way. Every round trip is checked against the sample. Nothing is written.
