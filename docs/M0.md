# BeeZip — M0 (Scaffold) Plan

This plan builds on [`PLAN.md`](PLAN.md) and keeps its decisions. Versions, licenses and API details were checked on 2026-11-01 against crates.io, npm, and the tauri-cli, ts-rs 12 and rmcp 3.8 sources.

## Scope
- A Cargo workspace and `rust-toolchain.toml`. Crate skeletons: `beezip-core`, `beezip-commands`, `beezip-mcp`, `beezip-cli` (bin `beezip`), `beezip-shell` (Windows cdylib stub) and `xtask`.
- The Tauri 2 + React-TS app shell in `apps/desktop` (productName `BeeZip`, identifier `app.beezip.desktop`), using pnpm.
- `deny.toml`, rustfmt/clippy config, `.editorconfig`, `.gitattributes`, the two licenses, a README stub and a `THIRD_PARTY_NOTICES` placeholder.
- GitHub Actions:
  - a `windows-latest` job running fmt, clippy `-D warnings`, test, cargo-deny, a Tauri build smoke test and the codegen staleness check;
  - an `ubuntu-latest` job running the core/commands/mcp/cli tests.
- One command, `app.version`, wired end to end through the registry:
  - `beezip version` and `beezip run app.version`;
  - the same command called through Tauri `cmd_run` and shown in the UI;
  - an MCP `tools/list` that lists it.

**Out of scope:** codecs and formats, MCP sandboxing, Explorer integration and fuzzing (fuzzing moves to M1).

## 3. Order of work
1. **Prerequisites.**
   - Enable pnpm with `corepack enable pnpm` from an elevated terminal. Node lives in `C:\Program Files\nodejs`, which non-admin users can't write to. The alternative is `corepack enable pnpm --install-directory <dir on PATH>`.
   - Install cargo-deny: `cargo install cargo-deny --locked`, or download the 0.20.2 Windows binary.
2. **Repo hygiene:** toolchain, `.gitattributes`, `.editorconfig`, rustfmt/clippy config, licenses, README, THIRD_PARTY_NOTICES and `.cargo/config.toml`. Done when `cargo -V` in the repo reports 1.99.1.
3. **Workspace and empty crates:** core, commands, mcp, cli, shell (cdylib) and xtask. Done when `cargo build` and `cargo clippy -- -D warnings` pass.
4. **`beezip-commands`:**
   - the Command trait, with `CLI`, `SURFACES` and `Effect::System`;
   - `CmdError`, including `InvalidArgs` and `Internal`, with `exit_code()`;
   - the full `JobEvent` enum (`#[serde(tag = "type")]`), `JobCtx`, `CancelToken` and `Interactor`;
   - the Registry;
   - a thread-per-job Engine that wraps `run` in `catch_unwind`;
   - `app.version`.

   Unit tests: lookup works, `{"bogus":1}` gives `InvalidArgs`, and a panicking test command gives `Internal`.
5. **CLI:**
   - global `--output human|json|ndjson`;
   - a subcommand for each registry entry that has a `CliSpec`, built with `Input::augment_args` and `from_arg_matches`, then serialised to a Value;
   - `run <name> [--json <json|@file|->]`, `commands`, `schema <name>`;
   - `assert_cmd` tests.

   The engine-to-CLI path now works end to end in the terminal.
6. **MCP:**
   - `list_tools` from the registry: MCP-visible commands only, names like `app_version`, input/output schemas, `readOnlyHint`/`destructiveHint` from `Effect`;
   - `call_tool` runs ReadOnly commands only, and refuses everything else until M2's Policy exists;
   - `beezip mcp` starts a current-thread tokio runtime; no other subcommand touches tokio;
   - `tests/mcp.rs` uses the rmcp client over `TokioChildProcess` on `CARGO_BIN_EXE_beezip`.
7. **`xtask codegen`** (§4); commit `commands.ts`.
8. **Desktop.** From `apps/`, run `pnpm create tauri-app desktop --template react-ts --manager pnpm --identifier app.beezip.desktop`, then:
   - rename the crate and lib, and inherit the workspace fields;
   - delete the member's `[profile.release]` (Cargo ignores member profiles, and it carries `panic = "abort"`);
   - set `crate-type = ["rlib"]`;
   - replace `greet` with `ipc.rs`: `cmd_run` and `cmd_list` fully implemented, `cmd_cancel` calling the engine, and `cmd_respond` returning `NotFound` until M3. Register the Engine with `.manage(Engine::new(registry()))`;
   - add `engine.ts`, and make `App.tsx` show `app.version` and the command list;
   - check the devtools console for CSP errors.
9. **`parity.rs`:** for every registry entry, (a) it is reachable via `beezip run`/`beezip schema`, (b) MCP `tools/list` has the same input schema (MCP-hidden commands excepted), and (c) its name is a key in `commands.ts`.
10. **`deny.toml`:** `cargo deny check` passes.
11. **CI:** push a branch and get both jobs green. Then break codegen on purpose once to watch the job fail.

## 4. TS bindings: ts-rs → `xtask codegen` → `src/gen/commands.ts`

```rust
// crates/beezip-commands/src/commands/app_version.rs
/// Show the BeeZip version and build information.
#[derive(Debug, Default, Deserialize, JsonSchema, clap::Args, TS)]
#[serde(deny_unknown_fields)]
pub struct AppVersionInput {}

#[derive(Debug, Serialize, JsonSchema, TS)]
pub struct AppVersionOutput {
    pub version: String,         // env!("CARGO_PKG_VERSION")
    pub commit: Option<String>,  // option_env!("BEEZIP_GIT_SHA"); set by CI, None locally; no build.rs
    pub platform: String,        // "windows-x86_64" from std::env::consts
    pub profile: String,         // "debug" | "release"
}
// impl Command for AppVersion { NAME = "app.version"; EFFECT = ReadOnly; CLI = Some(CliSpec { name: "version", aliases: &[] }) … }
```

How the pieces connect:
1. **The types derive `TS`, without `#[ts(export)]`.** `export` generates `#[test]` functions that write one file per type during `cargo test`, which is a side effect we don't want and the wrong shape.
2. **`register::<C>()` stores type-erased hooks.** It monomorphises function pointers into the entry: `run(Value) -> Value`, the clap hooks, the schemars schemas, and `ts_decls: fn(&ts_rs::Config, &mut BTreeMap<String, String>)`.
   - That hook walks `C::Input`, `C::Output` and their dependencies with a `ts_rs::TypeVisitor`.
   - It keeps only types where `T::output_path().is_some()`. Only derived types return one, so builtins drop out.
   - It stores `docs() + "export " + decl(cfg)` under `ident(cfg)`.
3. **The doc comment has one source.** It is read from the schemars `description` of the Input type and used as the clap `about`, the MCP description and (through ts-rs `docs()`) the JSDoc.
4. **`cargo xtask codegen` writes the file:**
   - It uses `Config::new().with_large_int("number")`. By default ts-rs maps u64/i64 to `bigint`, but serde, Tauri and MCP send JSON numbers, so `JobId` and byte counts would get the wrong type.
   - It walks the registry sorted by name and adds `JobEvent`, `CmdError`, `Effect` and `CommandInfo`.
   - It fails if two different declarations share a name, so types are named `<Command>Input`/`<Command>Output`.
   - It emits the `CommandMap`, normalises to LF, and writes only when the content changed:

   ```ts
   // @generated by `cargo xtask codegen` from the beezip-commands registry. Do not edit.
   export type AppVersionInput = Record<symbol, never>;
   export type AppVersionOutput = { version: string, commit: string | null, platform: string, profile: string, };
   export type JobEvent = { "type": "Started" } | { "type": "Finished", output: JsonValue } | /* … */;
   export type CommandMap = {
     /** Show the BeeZip version and build information. */
     "app.version": { input: AppVersionInput; output: AppVersionOutput };
   };
   export type CommandName = keyof CommandMap;
   ```
5. **`engine.ts` is the only hand-written consumer:**

   ```ts
   export function run<K extends CommandName>(name: K, args: CommandMap[K]["input"], onEvent?: (e: JobEvent) => void) {
     return new Promise<CommandMap[K]["output"]>((resolve, reject) => {
       const ch = new Channel<JobEvent>();
       ch.onmessage = (e) => { onEvent?.(e);
         if (e.type === "Finished") resolve(e.output as CommandMap[K]["output"]);
         else if (e.type === "Failed") reject(e.error);
         else if (e.type === "Cancelled") reject({ code: "Cancelled", message: "cancelled" }); };
       invoke("cmd_run", { name, args, onEvent: ch }).catch(reject);  // Rust `on_event` arrives camelCased
     });
   }
   ```

**How stale output gets caught**, at three levels:
- **CI:** `cargo xtask codegen` followed by `git diff --exit-code -- apps/desktop/src/gen`. A drift fails the job and prints the diff. `.gitattributes eol=lf` prevents false CRLF diffs on the Windows runner.
- **Type-check:** `pnpm build` (`tsc`) runs inside the Tauri smoke step, so UI code that no longer matches the bindings fails to compile.
- **Locally:** `cargo xtask codegen --check` compares in memory and exits 1 with "run `cargo xtask codegen`".

## 6. PLAN.md corrections (applied)
Planning M0 showed these points in PLAN.md to be wrong; PLAN.md has been updated:
1. **License policy (§2).** Tauri 2.12 depends on five MPL-2.0 crates, so "MPL denied" is now "per-crate exceptions". The apple-xar note changed with it.
2. **pnpm setup (Context).** `corepack enable pnpm` needs an elevated terminal here, and Node 25+ no longer ships corepack. The `packageManager` field pins the version.
3. **GUI binary name (Naming).** Tauri 2 names the binary after the Cargo bin. `mainBinaryName` renames it inside `target/`, which clobbers the CLI, so it stays unset until M3 packaging stages the CLI separately.
4. **`panic=abort` for the shell DLL (§1, §5).** Cargo can't set it per package, and it would make `catch_unwind` useless. The rule is now unwind + `catch_unwind` in every COM method, and the engine catches job panics as `CmdError::Internal`.
5. **Command engine (§1).** Added `CmdError::InvalidArgs`/`Internal`, the `CLI` and `SURFACES` trait consts, and `Effect::System`.
6. **Toolchain.** Pinned `1.99.1` instead of `1.99`.
7. **M0/M1 lists (§3, §4).** `git init` was already done; the default branch stays `master`. Fuzzing moves to a scheduled nightly workflow in M1.
