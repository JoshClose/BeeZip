# BeeZip — M1 (Engine + CLI) Plan

This plan builds on [`PLAN.md`](PLAN.md) and [`M0.md`](M0.md) and keeps their decisions, except where §11 corrects PLAN.md. Versions, licenses and features were checked on 2026-11-02 against crates.io. The APIs named here were checked in the sources of zip 9.2.2, lzma-rust2 0.23.0, zstd 0.14.3, bzip2 0.6.1, tar 0.4.46, file-format 0.29.0 and ts-rs 12.0.1. A scratch build of the whole dependency set below passes all four `cargo deny` checks once MIT-0 is allowed.

## Scope
- **beezip-core:**
  - the codecs: gzip, zlib, bzip2, xz, lzma, lzip, zstd, lz4, brotli and snappy, plus raw deflate on request;
  - detection, including codec chains such as `zstd → tar`;
  - the ZIP and TAR formats, plus a one-entry "stream" format so a bare `notes.txt.gz` opens like an archive;
  - `SafeFs`/`FsSink`, limits, progress and cancellation.
- **beezip-commands:**
  - `Policy`, `config.toml`, a `details` field on errors and a new `Unsafe` error code;
  - progress throttled to 10 Hz;
  - ten commands: `formats.list`, `file.detect`, `archive.{info,list,test,extract,create}`, `entry.read` and `stream.{compress,decompress}`.
- **beezip-cli:** subcommands for all ten, TTY prompts for passwords and overwrites, indicatif progress bars, Ctrl+C cancellation, `--quiet`, and trycmd snapshot tests.
- **Tests:**
  - round-trip proptests for every writable format;
  - third-party fixtures and a malicious corpus;
  - interop against 7-Zip (Windows CI) and GNU tar (Linux CI).
- **Fuzzing:** `fuzz/` with five cargo-fuzz targets. A workflow fuzzes each target for 10 minutes nightly and for 1 minute on PRs that touch core.

**Out of scope:**
- **M2:** MCP sandbox roots, elicitation and paging. The new read-only commands do appear in MCP `tools/list` from M1, because the tool list is built from the registry.
- **M3:** the index cache, GUI screens, and 7z/RAR/volumes.
- **M5:** the editing commands and the codepage override.
- **M6:** parallel gzip and parallel zip writing, which come with `bench.run`.

## 3. beezip-core

### 3.1 Errors and the job context
- **No serialization in core.** Core doesn't depend on serde, schemars, ts-rs or clap. `beezip-commands` owns every wire type and converts, so core types can change without changing the API that the CLI, the GUI and MCP see.
- **Errors.** `Error { kind: ErrorKind, message: String }`. Each `ErrorKind` is one of the `CmdError` codes core can produce: NotFound, UnsupportedFormat, UnsupportedOperation, PasswordRequired, WrongPassword, Corrupt, Unsafe, Conflict, LimitExceeded, Cancelled, Io and InvalidArgs. The conversion to `CmdError` is a 1:1 match.
- **The `Ctx` trait** is how core reaches the job without depending on `beezip-commands`:

  ```rust
  pub trait Ctx {
      fn is_cancelled(&self) -> bool;
      fn progress(&mut self, p: &Progress);   // JobCtx throttles to ~10 Hz; the last update always goes out
      fn warn(&mut self, message: String);
      fn password(&mut self, entry: Option<&str>, attempt: u32) -> Result<String, Error>;
      fn overwrite(&mut self, existing: &Path) -> Result<OverwriteChoice, Error>;   // only for policy `ask`
  }
  ```

  `JobCtx` implements it by forwarding to the job's `Interactor`. When an interactor fails (`PasswordRequired`, `Conflict` or `Cancelled`), the error comes back to core as the matching `ErrorKind`.
- **Reports, not errors, for partial results.** Extraction returns an `ExtractReport` and testing returns a `TestReport`. The command decides whether a report means failure (§4.1), so core errors never carry structured data.
- **Progress:** byte counts come from a `CountingReader` on the archive file, so they track compressed input.

### 3.2 Codecs

```rust
pub trait Codec: Sync {
    fn id(&self) -> CodecId;
    fn extensions(&self) -> &'static [&'static str];      // ".gz", and tar shorthands such as ".tgz"
    fn sniff(&self, head: &[u8]) -> Option<Confidence>;
    fn levels(&self) -> Option<Levels>;                    // { min, max, default }; None = no levels
    fn threads(&self) -> bool;
    fn decoder<'a>(&self, r: Box<dyn Read + 'a>, limits: &Limits) -> Result<Box<dyn Read + 'a>>;
    fn encoder<'a>(&self, w: Box<dyn Write + 'a>, opts: &EncodeOpts) -> Result<Box<dyn FinishWrite + 'a>>;
}
```

`FinishWrite` adds `finish(self: Box<Self>) -> io::Result<()>`, so trailers get written and errors surface. A dropped encoder must never truncate output silently.

| Codec | Extensions | Detected by | Decoder | Encoder | Levels (default) | Threads |
|---|---|---|---|---|---|---|
| gzip | .gz .tgz | `1F 8B 08` | flate2 `MultiGzDecoder` (concatenated members) | `GzEncoder` | 0–9 (6) | – |
| zlib | .zz .zlib | header check bits + extension | `ZlibDecoder` | `ZlibEncoder` | 0–9 (6) | – |
| deflate | – | never; `--codec deflate` only | `DeflateDecoder` | `DeflateEncoder` | 0–9 (6) | – |
| bzip2 | .bz2 .tbz .tbz2 | `BZh1`–`BZh9` | `MultiBzDecoder` | `BzEncoder` | 1–9 (9) | – |
| xz | .xz .txz | `FD 37 7A 58 5A 00` | `XzReader` (multi-stream); single-threaded in M1 (§11) | `XzWriter` / `XzWriterMt` | 0–9 (6) | ✓ |
| lzma | .lzma | properties byte and dictionary size checks, + extension | `LzmaReader` | `LzmaWriter` | 0–9 (6) | – |
| lzip | .lz .tlz | `LZIP` | `LzipReader` | `LzipWriter` / `LzipWriterMt` | 0–9 (6) | ✓ |
| zstd | .zst .tzst | `28 B5 2F FD`, and skippable frames | `zstd::stream::read::Decoder` + `window_log_max` | `Encoder` + `include_checksum(true)` + `multithread(n)` | 1–22 (3) | ✓ |
| lz4 | .lz4 | `04 22 4D 18` | `lz4_flex::frame::FrameDecoder` | `FrameEncoder`, content checksum on | none | – |
| brotli | .br | no magic: extension, confirmed by a trial decode | `brotli::Decompressor` | `CompressorWriter`, window 22 | 0–11 (9) | – |
| snappy | .sz | `FF 06 00 00 73 4E 61 50 70 59` | `snap::read::FrameDecoder` | `snap::write::FrameEncoder` | none | – |

- **Decoder memory:** `Limits::decoder_memory` (default 1 GiB) becomes xz's `new_mem_limit`, zstd's `window_log_max(30)`, and a memory-usage check before an lzma or lzip decode starts.
- **Defaults:** brotli defaults to 9 rather than its CLI's 11, which runs at about 1 MB/s. `XzReaderMt` needs `Read + Seek`, so it is used only when xz is the outer layer of a file.

### 3.3 Detection
1. Read the first 64 KiB into a `Probe { head, len, extension }`.
2. Every format and codec sniffs `head`. A sniffer returns `Certain` (magic plus a structural check, such as the tar header checksum), `Likely` (magic only) or nothing; `Guess` means a match on the extension only. The highest confidence wins, and the extension breaks ties.
   - **tar:** the `ustar` magic at offset 257, or a valid v7 header checksum.
   - **zip:** `PK\x03\x04`, or `PK\x05\x06` for an empty archive.
   - **zip SFX:** a PE file with an end-of-central-directory record within the last 64 KiB + 22 bytes. zip opens it with `ArchiveOffset::Detect`, which finds where the archive starts inside the exe.
3. When a codec matches, decode up to 64 KiB of its output and probe again, at most `max_layers` deep (default 4). `x.tar.zst` comes out as `[zstd, tar]`, and `notes.txt.gz` as `[gzip]` with the stream format.
4. When nothing matches, `FileFormat::from_bytes(head)` supplies a label such as "Portable Network Graphics". BeeZip's own sniffers decide everything else. file-format has no brotli or LZMA-alone signature, and it reports DOCX, JAR and EPUB as their own formats, while BeeZip opens them as ZIP.

### 3.4 Formats

```rust
pub struct Entry {
    pub id: usize,
    pub path: String,                // `/`-separated, decoded, exactly as stored; sanitising happens in FsSink
    pub raw_path: Vec<u8>,
    pub kind: EntryKind,             // File, Dir, Symlink { target }, Hardlink { target }, Other
    pub size: Option<u64>,
    pub packed_size: Option<u64>,
    pub modified: Option<SystemTime>,
    pub crc32: Option<u32>,
    pub method: Option<&'static str>,
    pub encrypted: bool,
    pub unix_mode: Option<u32>,
    pub dos_attrs: Option<u32>,
}
pub trait ArchiveReader {
    fn entries(&self) -> &[Entry];
    fn info(&self) -> ArchiveInfo;   // methods used, comment, encryption, solid, sfx
    fn extract(&mut self, sel: &Selection, sink: &mut dyn EntrySink, cx: &mut dyn Ctx) -> Result<()>;
    fn open_entry(&mut self, id: usize, cx: &mut dyn Ctx) -> Result<Box<dyn Read + '_>>;
}
pub trait EntrySink {
    fn entry(&mut self, entry: &Entry, data: &mut dyn Read, cx: &mut dyn Ctx) -> Result<()>;
}
pub trait ArchiveWriter {
    fn add(&mut self, entry: &NewEntry, data: &mut dyn Read, cx: &mut dyn Ctx) -> Result<()>;
    fn finish(self: Box<Self>) -> Result<()>;
}
```

There are three sinks: `FsSink` writes to disk (§3.5), `TestSink` hashes and discards for `archive.test`, and `NullSink` discards for the fuzzers. `add_raw_from`, which copies entries without recompressing them, waits for the editing commands in M5.

**ZIP** (zip 9.2.2):
- **Opening:**
  - `ZipArchive::with_config(Config { archive_offset: ArchiveOffset::Detect }, file)`.
  - If `has_overlapping_files()` reports that entries share compressed data, opening fails with `Unsafe`, because that is the overlapping-entry zip-bomb technique.
  - Entries come from `by_index_data(i)`, which reads metadata without touching the data.
- **Reading:**
  - `by_index_with_options(i, ZipReadOptions::new().password(pw))`.
  - `InvalidPassword` asks again, up to the retry limit (§4.1), and then gives `WrongPassword`. `UnsupportedArchive(PASSWORD_REQUIRED)` asks for a password.
  - A CRC mismatch on a ZipCrypto entry reports "wrong password or damaged data". ZipCrypto's one-byte password check lets 1 wrong password in 256 through, so the CRC is often the first sign.
- **Writing:**
  - `ZipWriter::new(file).set_auto_large_file()`, so Zip64 is used when needed.
  - `SimpleFileOptions` carries the method, level, DOS time and Unix permissions, plus an extended-timestamp extra field (0x5455, UTC mtime) added with `add_extra_field`.
  - **Encryption:** a password means AES-256 (`with_aes_encryption(AesMode::Aes256, pw)`). `--encryption zipcrypto` uses `zip::unstable::write::FileOptionsExt::with_deprecated_encryption`, for tools such as Windows Explorer that can't read AES.
- **Methods:** BeeZip writes Store, Deflate (zlib-rs, levels 0–9), Bzip2, Zstd, Xz and PPMd. It also reads Deflate64, LZMA and the legacy Shrink, Reduce and Implode.

**TAR** (tar 0.4.46):
- **Reading:**
  - One pass over `tar::Archive`. pax and GNU long names are handled by the crate.
  - Plain `.tar` files are seekable, so `raw_file_position()` lets `open_entry` seek straight to an entry. A compressed tar has to be rescanned from the start, so its `random_access` cap is false.
- **Entry types:** Regular and Continuous become File; Directory, Symlink and Link (hardlink) keep their kinds; GNU sparse files read as File. Devices and FIFOs become Other, which extraction skips with a warning.
- **Writing:** `tar::Builder`, with GNU long-name headers (the crate's default). Modes are real on Unix and 0o644/0o755 on Windows, which has no exec bit. Symlinks are written with `append_link`.

**Stream** (a bare compressed file):
- One entry, named from the gzip FNAME field if there is one, otherwise from the file name minus the codec extension.
- Its size comes from the xz index, or as a hint from the gzip ISIZE trailer (which is mod 2³²). Otherwise the size is unknown until the data is decoded.

**FormatCaps in M1** record what BeeZip offers, not what the crate could do. Append, delete, rename, solid, volumes and encrypted headers stay off for every format until M3 or M5.

| Format | list | extract | create | encrypt | random_access |
|---|---|---|---|---|---|
| zip | ✓ | ✓ | ✓ | AES-256, ZipCrypto | ✓ |
| tar | ✓ | ✓ | ✓ | – | ✓ |
| tar + codec | ✓ | ✓ | ✓ | – | – |
| stream | ✓ | ✓ | through `stream.compress` | – | – |

### 3.5 SafeFs and FsSink
FsSink is the only code that writes extracted files. It applies these rules to each entry path, in order.

**Rewritten**: extraction continues, and the rewrite is reported in `renamed`.
- `\` counts as a separator; `.` and empty components are dropped.
- A leading `/`, drive (`C:`), UNC (`\\server\share`) or `\\?\` prefix is stripped, so the path becomes relative.
- In each component, `<>:"|?*` and control characters become `_`. Replacing `:` also closes the NTFS alternate-data-stream hole.
- Trailing dots and spaces become `_`.
- Device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, their superscript-digit forms, `CONIN$`, `CONOUT$`) get a `_` prefix, with or without an extension.

**Refused**: the entry is skipped and recorded with a reason.
- **Any `..` component.**
- **A parent directory that leads outside `dest` through a symlink or junction.**
  - Directories are created one level at a time.
  - Each existing level is canonicalised and checked against the canonical `dest` before anything is created inside it, and checked directories are cached.
  - So a junction someone planted in `dest` can't redirect writes.
- **Links, when `links` is off** (the default).
  - With `links` on, a symlink is created only if its target resolves inside `dest`.
  - Symlinks are created after every other entry, so no entry in the same archive can be written through one.
  - Hardlinks are always extracted as copies of the earlier file, if that file is inside `dest`.

**Collisions.** If a later entry's path matches one already written by this job case-insensitively, the new entry is treated as an existing file and goes through the overwrite policy.

**Overwrite policy:**
- The choices are `ask`, `always`, `never`, `rename` (`name (1).ext`) and `newer`. The default comes from config, and the config default is `ask`.
- `ask` calls `Ctx::overwrite`. Replace all and Skip all hold for the rest of the job.

**Atomic writes.**
- Each file is written to `<name>.<random>.beezip-partial` in its target directory and then renamed over the final name.
- A Drop guard deletes the partial file on cancel, error or panic.
- Completed files and created directories stay.

**Metadata.**
- Files get their mtime after they are closed; directories get theirs at the end, deepest first.
- On Windows, the read-only attribute comes from the DOS attributes. On Unix, permission bits are restored, masked to 0o777.
- ACLs, xattrs and streams stored in the archive are not restored.

**Mark of the Web (Windows).** If the archive has a `Zone.Identifier` stream, the same stream is written to every extracted file. This is what Explorer does, and it keeps SmartScreen and Office Protected View aware that the files came from the internet. Set `extract.mark_of_the_web = "none"` in config to turn it off.

**Limits.** These come from config `[limits]`; MCP gets stricter values in M2. Declared sizes are never trusted: the checks count bytes actually written.

| Limit | Default | When exceeded |
|---|---|---|
| `max_ratio` | 10 000 : 1 per entry, checked after its first 64 MiB | LimitExceeded |
| `max_total_bytes` | unlimited | LimitExceeded |
| `max_entries` | 10 000 000 | LimitExceeded |
| `max_layers` | 4 codec layers | deeper layers are treated as data |
| `decoder_memory` | 1 GiB | LimitExceeded |

**Long paths.** Rust's std already turns long absolute paths into `\\?\` form on Windows. A 526-character path was checked with `create_dir_all`, `write`, `rename` and `read`. SafeFs therefore passes absolute paths and adds no prefixes itself; a test keeps it that way.

**The result.**
- Core returns an `ExtractReport`: files, dirs, links, bytes, `skipped[]` and `renamed[]`. Each list is capped at 1 000 items, with totals alongside.
- If any entry was refused, the command fails with `Unsafe` and puts the report in the error's `details`. The GUI can then say "10 files extracted, 2 unsafe entries skipped", and the CLI exits 14. The safe files are kept, and the failure can't be missed.
- Entries skipped by the `never` or `newer` policy are not errors.

### 3.6 Timestamps
- **ZIP:**
  - BeeZip takes the most precise time available: the NTFS extra field (UTC, 100 ns), then the extended timestamp (UTC, 1 s), then the DOS time (local, 2 s).
  - A DOS time is converted with the local UTC offset at that date (`time`'s `local-offset`). If that fails, as it can on Unix, it is read as UTC.
  - New zips get a DOS time and an extended timestamp.
- **TAR:** the header mtime (UTC, 1 s), or the pax `mtime` record when there is one.
- **On the wire:** RFC 3339 in UTC (`2026-11-02T14:03:00Z`). In the JSON schema that is `format: date-time`; in TS it is `string`. The human CLI output shows local time.

## 4. beezip-commands

### 4.1 Engine changes
- **`CmdError.details`:** an `Option<serde_json::Value>`, left out of the JSON when empty (`details?: JsonValue` in TS). It is used by:
  - `Unsafe`: the extract report;
  - `Corrupt` from `archive.test`: per-entry errors and counts;
  - `LimitExceeded`: `{ limit, value }`;
  - `PasswordRequired`: `{ "param": "password" }`.
- **`ErrorCode::Unsafe`:** exit code 14. It means the archive contains something BeeZip refuses to extract: an unsafe path, a link leading out of the destination, or overlapping entries.
- **`Policy`:** `{ read_only, roots: Option<Vec<PathBuf>>, limits }`.
  - A new trait method, `fn access(input: &Self::Input) -> Vec<Access>`, returns `Access::Read(path)` or `Access::Write(path)` items and defaults to empty.
  - The erased run hook checks the policy after deserialising the input and before calling `run`. `read_only` refuses every command that isn't ReadOnly with `UnsupportedOperation`.
  - `roots` refuses a write outside them with `OutsideSandbox`, checked on the canonicalised parent.
  - The CLI and the GUI pass `Policy::unrestricted()`. M2 wires up the MCP roots.
- **Config:** `%APPDATA%\BeeZip\config.toml` (`dirs::config_dir()`), or the file `BEEZIP_CONFIG` names.
  - A missing file means defaults, and unknown keys only warn.
  - A wrong type fails the command with `InvalidArgs` and the TOML line number.
  - It is read when the process starts; the `settings.*` commands come later.

  ```toml
  [extract]
  overwrite = "ask"          # ask | always | never | rename | newer
  links = false
  mark_of_the_web = "all"    # all | none

  [create]
  threads = 0                # 0 = one per core

  [levels]                   # per codec and zip method
  zstd = 3
  xz = 6
  gzip = 6
  deflate = 6
  bzip2 = 9
  brotli = 9

  [stream]
  codec = "zstd"             # default for `beezip compress`

  [limits]
  max_ratio = 10000
  max_entries = 10000000
  decoder_memory_mib = 1024  # no max_total_bytes = unlimited
  ```
- **`Engine::new(registry)`** keeps the defaults. The front ends call `Engine::with_options(registry, EngineOptions { config, policy })`.
- **`JobCtx`** gains:
  - `policy()` and `config()`;
  - the core `Ctx` adapter;
  - progress throttling;
  - password caching: after a password works, the rest of the job's entries use it;
  - up to three password prompts on `WrongPassword` when a TTY or the GUI can ask.
- **Threads:** the engine keeps one thread per job (§11).

### 4.2 Input conventions
- **Optional fields.** Required fields are plain types. Every optional field is an `Option<T>` or a `bool` flag, marked `#[serde(default, skip_serializing_if = …)]`, with `#[ts(optional_fields)]` on the struct.
  - TS callers can then write `run("archive.extract", { archive, dest })`.
  - Unset options are filled from config inside `run`, which is why they are `Option`s rather than serde defaults.
- **Enums** derive `clap::ValueEnum` and serde with the same kebab-case names. A test checks that every enum's clap names match its serde names.
- **CLI and JSON defaults agree.** A per-command test builds the Input once from the CLI with only the required arguments and once from JSON with only the required fields, and checks the two are equal. This catches a clap default drifting from a serde default.
- **Paths** are `PathBuf`, which is a `string` in the schema and in TS.
  - The CLI resolves relative paths against the current directory.
  - The GUI always sends absolute paths.
  - MCP's rules come in M2.
- **Passwords** use a `Secret` newtype. It is a plain string on the wire, `Debug` prints `***`, and it never reaches a log.
- **Unknown fields are rejected:** every Input keeps `#[serde(deny_unknown_fields)]`, as in M0.
- **Field names:** archive commands call the archive file `archive`, and `archive.list` calls the folder inside it `dir` (§11).

### 4.3 Commands

| Command | CLI | Positional | Options | Output |
|---|---|---|---|---|
| `formats.list` | `formats` | – | – | each format and codec: id, name, extensions, caps, methods, levels, threads |
| `file.detect` | `detect` | path | – | layers `[{kind, id, confidence}]`, chain (`"zstd → tar"`), sfx, label, whether the extension agrees |
| `archive.info` | `info` | archive | `-p` | chain; file/dir/link counts; size, packed size, ratio; methods; encryption (none, some, all); solid; sfx; comment |
| `archive.list` | `list`, `l` | archive, [dir] | `--flat`, `--glob`…, `--offset`, `--limit`, `-p` | entries, total, offset, has_more |
| `archive.test` | `test`, `t` | archive | `-p` | entries and bytes tested; fails with `Corrupt` and per-entry errors in `details` |
| `archive.extract` | `extract`, `x` | archive, [entries]… | `-o/--dest`, `--glob`…, `--exclude`…, `--strip-components`, `--smart`, `--overwrite`, `--links`, `-p`, `--dry-run` | dest, counts, bytes, skipped, renamed; a plan on dry run |
| `archive.create` | `create`, `c` | output, inputs… | `-f/--format`, `-m/--method`, `-l/--level`, `--threads`, `-p`, `--encryption`, `--exclude`…, `-L/--follow-links`, `--overwrite`, `--dry-run` | path, format, entries, bytes in and out, ratio |
| `entry.read` | `read` | archive, entry | `--index`, `--offset`, `--max-bytes`, `--encoding text\|hex\|base64`, `-p` | data, encoding, offset, bytes read, size, eof, lossy |
| `stream.compress` | `compress` | input | `-o`, `--codec`, `-l`, `--threads`, `--overwrite` | output, codec, bytes in and out, ratio |
| `stream.decompress` | `decompress` | input | `-o`, `--overwrite` | output, codecs, bytes in and out |

- **Selection** (extract's entries, `--glob` and `--exclude`; list's `--glob`; create's `--exclude`):
  - Entry paths use `/`, and a directory selects its whole subtree.
  - A pattern without `/` matches a name at any depth (`*.txt`); a pattern with `/` matches the whole path (`docs/**/*.md`). Matching uses globset and is case-insensitive on Windows.
- **Destination:** `dest` defaults to the current directory, as with `7z x`, `unzip` and `tar`. With `--smart`, a selection with more than one top-level item goes into `dest/<archive stem>/` (`a.tar.zst` → `a`). Explorer's "Extract here" uses `--smart` in M4.
- **`archive.create`:**
  - **Format:** `-f` takes `zip`, `tar`, `tar.gz`, `tar.bz2`, `tar.xz`, `tar.lzma`, `tar.lz`, `tar.zst`, `tar.lz4`, `tar.br` or `tar.sz`. Without `-f`, the output's extension decides (`.tgz` and the other shorthands included), and an unknown extension is `InvalidArgs`.
  - **`--method`** is zip-only: store, deflate, bzip2, zstd, xz or ppmd.
  - **Entry names:** each input is stored under its own name, so `src/` becomes `src/…`.
  - **The output file is never added to itself.** Links are stored as links unless `-L` is given.
- **Levels** are checked against the ranges `formats.list` reports. lz4 and snappy reject `--level`.
- **`entry.read`:**
  - `offset` is reached by decoding up to it, since a compressed entry can't seek.
  - `text` decodes UTF-8 lossily and sets `lossy` when it had to.
  - `max_bytes` defaults to 64 KiB, with a ceiling of 16 MiB; M2 lowers it to 256 KiB for MCP.
- **Duplicate names**, which are common in appended tars:
  - `list` shows every copy.
  - `extract` writes them in order, so the last one wins, as in tar.
  - `entry.read --index` picks a specific copy.
- **`stream.decompress`:**
  - It strips one codec layer per call.
  - The output name drops the codec extension. `.tgz`, `.tbz2`, `.txz`, `.tzst` and `.tlz` become `.tar`, and an unknown extension gives `<name>.out`.

## 5. CLI
- **Prompts:**
  - When stdin and stderr are both TTYs, a `TtyInteractor` answers prompts:
    - passwords use dialoguer's `Password`;
    - overwrites use `Select`, with Replace, Replace all, Skip, Skip all and Rename;
    - the progress bar is suspended while it asks.
  - Otherwise `NonInteractive` answers, so `PasswordRequired` says "pass --password" and `Conflict` says "pass --overwrite".
- **Progress:**
  - In human mode, when stderr is a TTY, an indicatif bar on stderr shows bytes done and total, rate, ETA and the current entry.
  - The new global `-q/--quiet` flag hides bars and info logs. Warnings still print.
  - `ndjson` streams the throttled events, and `json` prints only the result.
- **Ctrl+C:** the first press cancels the job, which removes the partial file and exits 130. The second press exits at once.
- **Human output:** aligned tables for `formats` and `list`, with local times, and a one-line summary for everything else.
- **Exit codes** are unchanged from M0, plus 14 for `Unsafe`.

## 6. Tests and fixtures
- **Codec round trips (proptest).**
  - Inputs: empty, tiny, incompressible and highly repetitive data up to 1 MiB.
  - Each codec runs at its lowest and highest level, including the multithreaded writers, and the output must decode back to the same bytes.
- **Archive round trips (proptest).**
  - The input is a random tree: names with spaces and non-ASCII characters, depth up to 4, empty files and directories, mixed compressibility and set mtimes.
  - Each tree is written in every writable combination:
    - zip × {store, deflate, bzip2, zstd, xz, ppmd} × {no password, AES-256, ZipCrypto};
    - tar and every tar + codec.
  - Extracting it must give the same bytes and the same mtimes. DOS-only zip times match to 2 s; BeeZip's own zips carry an extended timestamp and match to the second.
  - 32 cases per combination by default; set `PROPTEST_CASES` for more.
- **Third-party fixtures** live in `tests/fixtures/thirdparty/`, under 1 MiB in total.
  - `manifest.json` records each file's producer, chain, password and expected entries (path, kind, size, SHA-256).
  - `make-thirdparty.ps1` records the exact commands that made them.
  - Info-ZIP, macOS ditto and WinRAR samples come later.

  | Producer | Archives |
  |---|---|
  | 7-Zip 26.00 | zip with Store, Deflate, Deflate64, BZip2, LZMA, PPMd, AES-256 and ZipCrypto; a zip SFX; gzip, bzip2 and xz files |
  | GNU tar 1.35 (Git for Windows) | ustar, gnu and pax archives with long names, a symlink and a hardlink |
  | bsdtar 3.8.9 (Windows `tar.exe`, which has liblzma, bzip2 and zstd built in) | tar.gz, tar.xz, tar.zst and zip |
  | .NET, through PowerShell `Compress-Archive` | zip with non-ASCII names |
- **Malicious corpus.** `cargo xtask gen-fixtures` writes `tests/fixtures/malicious/`, which is committed so the fuzzers can use it too.
  - **Paths:** `../` traversal; absolute, drive and UNC paths; `CON` and `aux.txt`; `a:b`; a trailing dot.

  - **Checks:** each case must give its expected error code or skip reason. The test lists the destination's parent before and after, so it fails if anything was written outside the destination.
- **Interop:**
  - **Windows (7-Zip):**
    - Every archive the round-trip test writes must also pass `7z t`.

- **CLI (trycmd)** cases:
  - `--help` for every subcommand, `formats`, `detect` on fixtures, and `list --output json`;

  - a missing password without a TTY: exit 6;

- **Smoke test:** the PLAN §4 smoke test, with its `archive` field name fixed (§11).
- **Input parity:** the CLI-versus-JSON defaults test and the enum-names test from §4.2. The M0 parity test already covers `run`, `schema`, MCP and TS for every new command.

## 7. Fuzzing
- **Layout:** `fuzz/` is a cargo-fuzz project with its own `[workspace]`, excluded from the main one. The seed corpus is `tests/fixtures/` (libFuzzer reads corpus directories recursively).
- **Targets:**
  - `detect` takes any bytes.
  - `zip` and `tar` open the input, list it, and extract every entry into a `NullSink`.
  - `codecs` uses the first byte to pick a codec, then decodes the rest under tight limits.
  - `paths` checks the sanitiser's invariants. The result must be relative and stay under `dest`, with no `..`, no device name and no forbidden character.
- **`.github/workflows/fuzz.yml`:** expressions stay in block-style YAML, never inside `{ }` (see M0's CI fix).

```yaml
name: Fuzz
on:
  schedule:
    - cron: "23 3 * * *"          # nightly; scheduled runs use the default branch (master)
  pull_request:
    paths: ["fuzz/**", "crates/beezip-core/**"]
  workflow_dispatch:
permissions: { contents: read }
jobs:
  fuzz:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    strategy:
      fail-fast: false
      matrix:
        target: [detect, zip, tar, codecs, paths]
    env:
      SECONDS_PER_TARGET: ${{ github.event_name == 'schedule' && '600' || '60' }}
    steps:
      - uses: actions/checkout@v7
      - run: rustup toolchain install nightly --profile minimal
      - uses: taiki-e/install-action@v2
        with:
          tool: cargo-fuzz@0.13.2
      - uses: actions/cache@v6
        with:
          path: fuzz/corpus/${{ matrix.target }}
          key: fuzz-corpus-${{ matrix.target }}-${{ github.run_id }}
          restore-keys: fuzz-corpus-${{ matrix.target }}-
      - name: Fuzz ${{ matrix.target }}
        run: >
          cargo +nightly fuzz run ${{ matrix.target }} fuzz/corpus/${{ matrix.target }} tests/fixtures
          -- -max_total_time=$SECONDS_PER_TARGET -rss_limit_mb=2048
      - if: failure()
        uses: actions/upload-artifact@v7
        with:
          name: crash-${{ matrix.target }}
          path: fuzz/artifacts/${{ matrix.target }}
```

## 11. PLAN.md corrections (applied)
Planning M1 showed these points in PLAN.md to be wrong or incomplete. PLAN.md was updated when this plan was approved on 2026-11-02, along with the §12 decisions as written.
1. **License allowlist (§2):** add MIT-0, for `ppmd-rust`, which zip's PPMd support uses.
2. **ZIP row (§2):** zip 9.2.2 writes PPMd. BeeZip's deflate uses zlib-rs without zopfli, so levels stop at 9. ZipCrypto writing goes through zip's `unstable` API. `lzma-rust2` is pinned to `=0.23.0`, the version zip needs.

4. **Raw deflate (§2):** it has no magic and no extension, so it is never detected; `--codec deflate` only.
5. **Detection (§1):** BeeZip's own sniffers decide. `file-format` only labels files that aren't archives.
6. **SafeFs (§1):** spell out the rewrite/refuse split (§3.5) and say how links work: symlinks are deferred to the end and hardlinks are extracted as copies. Leave long paths to std. **New:** Mark-of-the-Web propagation.
7. **`CmdError` (§1):** add the `Unsafe` code (exit 14) and the `details` field.
8. **Command trait (§1):** add `fn access(input) -> Vec<Access>`, which is how the engine enforces `Policy`.
9. **Engine (§1):** keep one thread per job instead of a worker pool. Jobs are few and long, and the codecs bring their own threads.
10. **Index cache (§1):** moves to M3, where the GUI pages through large archives.
11. **Core and commands (§1):** core has no serde, schemars or ts-rs; `beezip-commands` owns the wire types.
12. **Field names (§1, §4):** every archive command names the archive `archive`. `archive.list`'s folder argument is `dir`, not `path`. The §4 smoke test becomes `{"archive":"t.tar.zst"}`.
13. **Fixtures (§4):** the first third-party set uses the tools available on Windows: 7-Zip, GNU tar, bsdtar and .NET. Info-ZIP, ditto and WinRAR samples follow later.
14. **Fuzzing (§3, §4):** besides the nightly run, the workflow fuzzes each target for a minute on PRs that touch core or `fuzz/`.

### Found while building PR 1 (core)
The crate APIs differed from this plan in a few places, and building core settled some details the plan left open. The code follows these; the sections above were corrected where they would otherwise mislead.

**Crate APIs**
1. **xz decoding (§3.2):** lzma-rust2 0.23's `XzReaderMt` takes no memory limit, so M1 decodes xz on one thread (`XzReader::new_mem_limit`) to keep `decoder_memory` enforced. The multithreaded writers are unchanged. Multithreaded decoding returns with `bench.run` in M6, behind a check of the block headers' dictionary sizes.
2. **lzip (§3.2):** `LzipReader` has no memory limit either, so the decoder reads the first member's dictionary size from its header and checks it first. Lzip caps dictionaries at 512 MiB.
3. **lz4 (§3.2):** lz4_flex's `FrameDecoder` returns end-of-stream after the first frame. A wrapper decodes concatenated frames, as the `lz4` CLI does.
4. **brotli (§3.2):** `CompressorWriter::into_inner` finishes the stream but swallows write errors, so the encoder writes through a latch that keeps the first one.
5. **zstd (§3.2):** `SrcSizeHint` is behind zstd's `experimental` feature. The encoder pledges the size only when the caller knows it exactly (`EncodeOpts::size_exact`). The LZMA-family encoders shrink their dictionary to fit a known small input, so high levels don't allocate hundreds of MiB for a small file. zstd's "window too large" error comes back as `LimitExceeded`, not `Corrupt`.
6. **Zip levels (§3.4):** zip deflate runs through flate2, whose fastest level is 1, so zip deflate is **1–9** (6), not 0–9. The other ranges are bzip2 1–9 (9), zstd 1–22 (3), xz 0–9 (6) and PPMd 1–9 (7). Store has no levels.
7. **Zip times (§3.6):** zip 9.2.2 exposes extra fields only on an opened entry. BeeZip therefore reads the NTFS and extended-timestamp fields from the central directory itself, through a second file handle.
8. **Atomic writes (§3.5):** tempfile's `persist` calls `MoveFileExW` without std's long-path handling and fails beyond 260 characters. FsSink and `archive.create` rename with `std::fs::rename` instead; the temp path's drop guard still cleans up.
9. **file-format (§1, §3.3):** without features it names every `MZ` file "MS-DOS Executable". The `reader-exe` and `reader-txt` features give "Portable Executable" (the §10 check on explorer.exe) and "Plain Text".

**Interfaces**

10. **`ArchiveReader` (§3.4):** `entries(&mut self, cx) -> Result<&[Entry]>` and `info(&mut self, cx)`, plus `format()`. A compressed tar has to be decoded to build its index, so the index is built on first use. `extract` streams in one pass without it, so extracting a `tar.zst` decodes it once.
11. **Sniffers (§3.2, §3.3):** `sniff` takes the whole `Probe` (head, tail, length and name), not just `head`. zlib, lzma and brotli need the extension; zip and SFX need the tail; brotli's trial decode needs to know whether the head is the whole file.
12. **Opening and whole operations:** `source.rs` holds `Source` (the file plus its codecs, reopened for each pass) and `open()`. A new `ops.rs` has `create`, `extract` and `test` for the commands to call, and `sinks.rs` has `TestSink` and `NullSink`. The fuzz targets share `fuzz_targets/common.rs`. `ArchiveKind` maps `-f` names and output extensions.

**Rules settled**

13. **Detection (§3.3):** an extension-only `Guess` doesn't stand against content that file-format recognises, so a PNG named `a.zip` is a PNG.
14. **Drive prefixes (§3.5):** a drive is stripped only when a separator or the end follows (`C:\x`, `C:`). `a:b` is a name with a stream in it: it becomes `a_b`, and `C:x` becomes `C_x`. Either way nothing leaves the destination.
15. **Symlinks (§3.5):** a target is resolved from the link's location. `..` after a component that is itself a link is refused, and so is a link located under another link. Otherwise an in-tree link to an ancestor could carry a second link out.
16. **Hardlinks (§3.5):** copies produce data without consuming input, so their bytes are held to `max_ratio` against the job's whole input and count toward `max_total_bytes` (`FsOptions::input`, `FsOptions::budget`).
17. **Duplicate names (§3.5, §4.3):** an exact repeat of a path this job wrote is replaced (last wins, as in tar). A clash that differs only in case goes through the overwrite policy.
18. **Wrong passwords (§3.4):** a CRC failure on a ZipCrypto entry, or a failed AES authentication code, is `WrongPassword` with "wrong password or damaged data".

**Tests and tooling**

19. **Fixtures (§6):** Windows bsdtar 3.8.9 crashes (0xC0000005) on any non-ASCII name, so its fixtures use an ASCII-only copy of the tree. .NET and 7-Zip cover non-ASCII names. 7-Zip only makes 7z SFX modules, so the zip SFX fixture is 7-Zip's deflate zip behind a minimal PE stub. There are 20 fixtures, 165 KiB in all.
20. **Speed:** the pure-Rust codecs are optimised in dev builds (`[profile.dev.package.*]`). Unoptimised, the proptests crawl.
21. **Fuzzing on every platform:** `tests/mutations.rs` runs the five fuzz targets' bodies over every fixture and over bit-flipped, truncated and spliced copies of each, within `cargo test`. cargo-fuzz itself only runs on Linux nightly. `fuzz.yml` also creates the corpus directory and has a concurrency group.

## 12. Decisions (approved 2026-11-02)
These were the calls most likely to go the other way. Each was approved as the first option:
- **Unsafe entries:** skip them, finish the rest, then fail with `Unsafe` (exit 14). The alternative is to stop at the first one.
- **Default destination:** the current directory, like `7z x`, `unzip` and `tar`, with `--smart` to opt in to a folder. The alternative is to always extract into a folder named after the archive.
- **Mark of the Web:** on by default, like Explorer. In 7-Zip it is an option (`-snz`).
- **Ratio limit for the CLI and GUI:** 10 000 : 1. Deflate tops out near 1 000 : 1, but zstd and xz on zeros go far higher.
- **Default codec for `beezip compress`:** zstd. gzip is more widely readable.
- **Two PRs** (core, then commands and CLI) rather than one.
